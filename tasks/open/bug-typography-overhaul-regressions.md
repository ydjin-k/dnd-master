# bug-typography-overhaul-regressions

Размер: S

Зона: `ui-shell`. Роль-исполнитель — `ui-developer` (см. `gamestudio/roles/ui-developer.md` и
`roles/_common.md`), не `developer`.

## Контекст

Владелец продукта потестировал вживую после мёржа `ui-visual-and-sound-polish` и
`ui-typography-overhaul` и нашёл три регресса — не пожелания, поведение реально сломано/не то, что
задумывалось изначально.

## Что нужно

### 1. Бестиарий: текст вылезает за рамку статблока

На «Бестиарии» текст особенностей/действий существа выходит за пределы карточки статблока (видно на
глаз при обычном окне, не только при ресайзе). Причина, вероятнее всего, в CSS-изменениях
`ui-visual-and-sound-polish`/`ui-typography-overhaul` (новые размеры шрифта/`line-height` в
`theme.css`, или что-то в `BestiaryPage.css`), не в самой вёрстке `BestiaryPage.tsx`. Найти и
починить перенос текста внутри рамки на всех трёх существах (Волк/Оборотень/Разбойник) и на длинных
описаниях действий/особенностей.

### 2. Бестиарий: изображения обрезаны на 25-50%

Картинка существа в детальной панели показывает только часть изображения (видно на глаз — портрет
явно обрезан по краям, не помещается целиком). Скорее всего `object-fit: cover` там, где нужен
`object-fit: contain` (или аналогичная проблема с фиксированной высотой рамки, обрезающей широкое/
высокое изображение) — картинка должна вписываться в рамку целиком, даже если это значит показывать
её мельче, а не обрезанной.

### 3. Бестиарий: подгрузка изображения после захода в раздел заметно долгая

Сейчас картинка запрашивается через `invoke("get_bestiary_image", ...)` только после выбора существа
в списке (см. `BestiaryPage.tsx`) — заметная пауза перед показом. Владелец хочет видеть изображение
сразу при заходе в раздел, без ожидания. Решение — на усмотрение исполнителя (предзагрузка всех
изображений бестиария при монтировании страницы, кэш уже загруженных data-URL между переключениями
существ, что-то ещё), но пауза должна исчезнуть.

### 4. Список снаряжения предыстории — жирным весь список вместо только заголовка

Регресс `ui-typography-overhaul`: в `CharacterWizard.tsx`, шаг «Итог», строка «Снаряжение: …» сейчас
оборачивает КАЖДЫЙ предмет в `<strong>` (весь список жирный). По исходному замыслу карточки
`ui-typography-overhaul` жирным должно быть только слово «Снаряжение:» и названия особенностей
предыстории/расы/класса (уже правильно сделано для `background.feature` через `EmphasizedText`) — не
перечисляемые предметы снаряжения. Убрать `<strong>` с самих предметов инвентаря в этом месте, оставить
список обычным текстом.

## DoD

- Статблок существа в бестиарии не переполняется — весь текст виден внутри рамки на всех трёх
  существах.
- Изображение существа показывается целиком (не обрезано), пусть мельче, если нужно для целого показа.
- Изображение существа видно сразу при заходе в раздел «Бестиарий», без заметной паузы.
- В мастере персонажа список предметов снаряжения предыстории на шаге «Итог» — обычным текстом, не
  жирным; слово «Снаряжение:» и названия особенностей остаются жирными, как было задумано.
- `$GATES_CMD` зелёный.

## Критерии приёмки

- Открыть «Бестиарий», выбрать «Оборотень» (самый длинный текст особенностей/действий из трёх) —
  весь текст читается внутри рамки, ничего не обрезано и не вылезло за край.
- Изображение любого из трёх существ видно целиком, не обрезанным по краям.
- Зайти в «Бестиарий» с чистого старта — изображение уже выбранного/первого существа появляется без
  заметной задержки.
- Создать персонажа через мастер, дойти до «Итога» — «Снаряжение: …» обычным шрифтом, не жирным.

## Критерии тестирования

- Регрессионный тест (если тестируемо через RTL/снапшот CSS-класса) на то, что элементы предметов
  снаряжения не получают класс/тег выделения на шаге «Итог».
- Остальное — визуальная проверка (кадры до/после в `docs/qa/evidence/`), автотест на CSS-переполнение
  текста не осмысленен для jsdom.
