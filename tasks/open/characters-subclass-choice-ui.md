# characters-subclass-choice-ui

Размер: L (общий механизм + 3 реальных случая, один из них — Круг земли — тянет за собой содержательный
объём справочных данных SRD, см. «Как поступить, если не успеваешь» ниже).

## Контекст

Карточки `characters-subclass-features-have-no-mechanical-effect` и
`characters-subclass-features-remaining-archetypes` (см. `tasks/DONE.md` #70, #73) дали механический эффект
почти всем архетипам, кроме мест, где особенность — это **выбор игрока**, а не то, что даётся безусловно.
`grants` в `characterCreationData.ts` умеет только «дать всегда», выбора «одно/N из списка» в приложении нет
вообще. Найдено 3 таких места (не считая «Тайных воззваний» Колдуна — см. ниже, почему не в этой карточке):

1. **Следопыт, «Добыча охотника»** (`classes-ranger`, архетип «Охотник», 3 уровень) — выбор 1 из 3 умений.
2. **Бард, Коллегия знаний** (`classes-bard`, 3 уровень) — выбор 3 навыков из полного списка навыков (не
   маленький фиксированный список — все ~18 навыков SRD).
3. **Друид, Круг земли** (`classes-druid`, 2 уровень) — выбор местности (SRD 5.1: Арктика, Побережье, Пустыня,
   Лес, Равнина, Гора, Болото); выбранная местность открывает свою таблицу заклинаний на 3/5/7/9 уровнях (это
   не разовый грант, а мини-`spellsByLevel` внутри варианта).

**Не включать в эту карточку:** «Тайные воззвания» Колдуна (`classes-warlock`, 2 уровень) — по SRD их можно
менять при каждом левел-апе колдуна, это принципиально другая форма выбора («изменяемый набор», не «выбрал
раз и навсегда»). Владелец продукта решил делать это отдельной карточкой позже — не браться за неё здесь,
даже если останется время.

## Где уже есть подходящий паттерн — не изобретать заново

В `CharactersPage.tsx` `requestLevelUp()` уже умеет прерывать левел-ап и открывать панель выбора **до**
применения `applyLevelUp` — так уже работает выбор архетипа на `chosenAtLevel` (радио-кнопки по
`levelUpSubclassInfo.subclasses`, см. `subclassPanelOpen`/`subclassChoiceIndex`/`confirmSubclass`) и ASI на 4
уровне (`asiPanelOpen`). Новый выбор архетипа — третья ветка того же прерывания, тем же принципом: если на
новом уровне у архетипа есть choice с `minLevel <= newLevel` и он ещё не сделан — сначала показать панель,
применить левел-ап только после выбора.

## Что нужно

1. **Данные**: `SubclassGrants` получает необязательное поле
   `choices?: SubclassChoice[]`, где
   ```ts
   interface SubclassChoice {
     id: string;        // стабильный id выбора, напр. "hunter-prey", "college-of-lore-skills"
     name: string;       // название особенности для панели/карточки
     minLevel: number;
     pick: number;        // сколько вариантов выбрать (1 для Следопыта/Друида, 3 для Барда)
     options: { id: string; label: string; grants: SubclassGrants }[];
   }
   ```
   Каждый вариант — это фрагмент `SubclassGrants` (владения/ресурсы/`scaling`/`spellsByLevel`/навыки и т.д.),
   который подмешивается к обычным грантам архетипа при выборе. **Не заводить отдельную систему** — вариант
   Круга земли просто кладёт свою местную таблицу заклинаний в `grants.spellsByLevel` этого варианта, и она
   пойдёт через уже существующий `subclassSpellsUpToLevel`.
2. **Модель персонажа**: новое поле `subclassChoices: Record<string, string[]>` (id выбора → id выбранных
   вариантов) — и в `src/state/types.ts`, и в `src-tauri/src/model.rs` (структурный `#[serde(default)]` уже
   есть на `Character`, отдельно ничего не нужно для обратной совместимости, см. `tool_proficiencies` как
   образец из карточки #73).
3. **Функция чтения эффективных грантов**: место, где сейчас `subclassGrants(classId, subclass)` отдаёт
   гранты архетипа, должно домешивать гранты выбранных вариантов персонажа (нужен доступ к
   `character.subclassChoices`, не только к `classId`/`subclass` — сигнатура скорее всего меняется или
   появляется параллельная функция `effectiveSubclassGrants(character)`; решить на месте, не ломая
   существующих вызовов там, где выбора ещё не было).
4. **Левел-ап**: `requestLevelUp()` — третья ветка прерывания: если на `newLevel` появляется ещё не сделанный
   `choice`, открыть панель вместо мгновенного `applyLevelUp`.
5. **UI панели** — два варианта, оба на карточке персонажа рядом с уже существующими панелями архетипа/ASI:
   - `pick === 1`: радио-кнопки, тем же визуальным паттерном, что уже есть у выбора архетипа.
   - `pick > 1`: чекбоксы с потолком ровно `pick` (нельзя отметить больше — как в мастере персонажа уже
     реализован выбор фиксированного числа навыков/языков, переиспользовать тот же приём, если он есть).
6. **Три конкретных случая** (SRD 5.1, `rules.json`/PDF как источник):
   - Следопыт «Добыча охотника»: 3 варианта умения (SRD).
   - Бард «Дополнительные навыки»: `options` — все навыки SRD (владелец варианта уже не даёт новый навык,
     если он уже есть — как и любой другой источник владений в приложении, сверить с существующей логикой
     объединения `skillProficiencies`).
   - Друид Круг земли: 7 местностей, у каждой — свои заклинания на 3/5/7/9 уровнях (2-5 круг) — самый
     объёмный пункт, содержательные данные из SRD, а не только код.

## Как поступить, если не успеваешь за одну сессию

Порядок по возрастанию объёма: сначала общий механизм + Следопыт (проверяет весь путь целиком, вариантов
всего 3), затем Бард (простой список без содержательного объёма), Круг земли — последним и по возможности
хотя бы с частью из 7 местностей, а не все сразу. В отчёте явно назвать, что из трёх случаев реально подключено
и что осталось.

## DoD

- Общий механизм выбора работает и покрыт тестами независимо от конкретных архетипов.
- Хотя бы «Добыча охотника» подключена целиком (простейший случай, доказывает путь).
- Существующий выбор архетипа/ASI на левел-апе не сломан.
- `$GATES_CMD` зелёный, и отдельно `cargo test` (модель персонажа тронута).

## Критерии приёмки

- Следопыт левел-апится до 3 уровня — левел-ап останавливается, показывает панель «Добыча охотника» с 3
  вариантами, после выбора персонаж получает эффект выбранного варианта, и он виден на карточке.
- Повторный левел-ап того же персонажа не переспрашивает уже сделанный выбор.
- Сохранение/загрузка кампании не теряет сделанный выбор.

## Критерии тестирования

- Для общего механизма: тест на «выбор недоступен до уровня», «выбор доступен и применяется», «выбор не
  спрашивается повторно», «pick > 1 не даёт выбрать больше N».
- Для каждого подключённого случая — минимум одна положительная и одна отрицательная проба (как в карточках
  #70/#73).
