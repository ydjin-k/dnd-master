# characters-gender-and-age

Размер: S

## Что нужно

На шаге "Итог" мастера персонажа (`src/ui/CharacterWizard.tsx`), рядом с именем/мировоззрением —
два новых поля:

- **Пол** — выпадающий список ровно из двух вариантов: "Мужской" / "Женский". Без третьего варианта
  — владелец продукта явно попросил только два. Дефолт — любой из двух (не оставлять пустым, тот же
  принцип, что уже применён к мировоззрению: "персонаж не может быть без пола").
- **Возраст** — обычное число, без ограничений по диапазону/расе (не хардкодить "разумные" границы
  по SRD-тексту о продолжительности жизни расы — это на усмотрение игрока/мастера, не блокер формы).

## DoD

- `Character` (и `src/state/types.ts`, и `src-tauri/src/model.rs`) получает поля `gender: string` и
  `age: number` — со `#[serde(default)]`-совместимым дефолтом на Rust-стороне (там уже есть паттерн
  `#[serde(rename_all = "camelCase", default)]` на структуре `Character` — новые поля просто
  подхватятся, доп. атрибут не нужен, см. как это уже сделано для `alignment`/`languages`).
- Оба поля попадают в готовый `Character` при создании через мастер.
- `ImportPage.tsx` (сохранение персонажа из импортированного текста) тоже проставляет дефолт для
  обоих новых полей (как уже сделано для `alignment: "Нейтральный"`) — не оставлять их
  неинициализированными.
- Карточка персонажа (`CharactersPage.tsx`) показывает пол и возраст в строке с расой/классом.

## Критерии приёмки

- Реальный сценарий: создать персонажа через мастер, выбрать пол "Женский", возраст "134" —
  готовый персонаж в списке (`CharactersPage`) показывает и то, и другое.

## Критерии тестирования

- Тест в `src/ui/CharacterWizard.test.tsx`: выбрать пол и возраст на "Итоге", создать персонажа,
  проверить оба поля в объекте, переданном в `addCharacter`.
- Тест на дефолт из импорта (`src/ui/pages/ImportPage.test.tsx`) — сохранённый персонаж имеет
  непустые `gender`/`age` по умолчанию.
- `$GATES_CMD` (`npm run gate`) зелёный целиком — это включает и `cargo test`, так что новые поля
  в Rust-модели не должны сломать существующие тесты (`character_without_new_fields_deserializes_with_defaults`
  и т.п.).
