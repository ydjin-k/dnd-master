# engine-gm-fact-store

Зона: `engine`. Размер: S. Роль: Developer.
Предусловие: `engine-gm-core-state` слита. Может идти параллельно с `engine-gm-seed-and-rng`.

Основание: ADR 0001, раздел 3 и раздел 6 пункт 1. ТЗ: §4.6, §6.3, §27.

## Зачем — и почему до Оракула

Fact — подтверждённый факт мира: дверь заперта, у комнаты есть второй выход, трактирщик знает
героя. §6.3 — **жёсткое правило, а не пожелание**: Оракул не бросается, если ответ уже есть в
состоянии мира.

Оракул, сданный раньше Fact Store, будет перебрасывать уже решённый факт — то есть **противоречить
игроку**: минуту назад дверь была заперта, теперь нет. Поэтому Fact Store идёт первым, и §41 ставит
его четвёртым пунктом против седьмого Оракула.

## Что нужно

`gm/facts.rs`:

- `EngineState.facts: Vec<Fact>` — **поле состояния, отдельного хранилища нет**;
- `Fact` по §4.6: субъект, предикат, значение, источник (`oracle` / `exploration` / `event` /
  `master`), достоверность;
- `create_fact`, `update_fact` — единственные, кто пишет; запись идёт `Mutation`-ом через
  `mutate::apply`, как всё остальное;
- **поиск факта по субъекту и предикату** — это и есть то, ради чего карточка существует: им
  будет пользоваться Оракул.

Показ: факты видны игроку в панели «Активно» (§29.1). Минимальный список, без фильтров и
сортировок.

## Чего НЕ делать

- Не заводить второе хранилище фактов и не класть их в отдельный файл.
- Не заводить `certainty` со сложной шкалой: §4.6 даёт `confirmed`, большего в v0.1 не нужно.
- Не удалять факты. §4.6: после создания факт не перепроверяется, **пока событие явно не изменит
  состояние**, — значит изменение это `update_fact`, а не удаление и создание заново.
- Не трогать Оракул — его ещё нет.

## DoD

- Факт создаётся, ищется по паре «субъект + предикат» и меняется; пишется только через
  `mutate::apply`.
- Факты переживают сохранение и загрузку.
- Факты видны на экране.
- **Отрицательная проба:** создать два факта с одной парой «субъект + предикат» — второй обязан
  быть отказом или обновлением первого, но не дублем. Два ответа на один вопрос — это ровно тот
  класс, ради которого §6.3 написан.
- `$GATES_CMD` зелёный, числа названы.

## Критерии приёмки

- Первой строкой отчёта: **что происходит при повторном создании того же факта** и почему выбрано
  именно это.
- Названо числом: проб было / стало.

## Критерии тестирования

- **Наблюдаемым поведением игры:** в живом окне создать факт из сцены, увидеть его в панели
  «Активно», перезапустить приложение — факт на месте.
- Порт 1420 занят владельцем: свой порт, свой bundle id, гасить только по PID своего запуска,
  `taskkill //IM dnd-master.exe` ЗАПРЕЩЁН.
