# bug-dead-combatant-occupancy

Размер: S

## Что не так

Бэкенд (`src-tauri/src/combat.rs`, `is_occupied`) намеренно разрешает вставать на клетку поверженного
бойца (`current_hp > 0` в проверке занятости) — труп не блокирует движение. Но фронтенд
(`src/ui/pages/CombatPage.tsx`, `combatantAt`) ищет ЛЮБОГО бойца на клетке без учёта HP:

```ts
function combatantAt(x: number, y: number) {
  return combat!.combatants.find((c) => c.x === x && c.y === y);
}
```

И клик по клетке сначала проверяет `combatantAt` — если труп там есть, клик ВЫБИРАЕТ труп вместо
того, чтобы переместить туда выбранного бойца. Игрок физически не может кликом переместиться на
клетку с телом поверженного, хотя правила боя это явно разрешают.

Найдено внешним ревью (Codex), подтверждено чтением `CombatPage.tsx:84-97`.

## DoD

- Клик по клетке с поверженным бойцом (и без живых бойцов на той же клетке) двигает выбранного
  бойца туда, а не выбирает труп.
- Клик по клетке с ЖИВЫМ бойцом продолжает выбирать его, как раньше.
- Труп визуально остаётся виден на клетке (не убирать его из рендера) — меняется только то, что
  he перестаёт быть "кликабельной целью выбора" для перемещения.

## Критерии приёмки

- Реальный сценарий: в бою поверженный боец лежит на клетке (x,y); выбранный живой боец кликает по
  этой клетке — движение происходит (`moveCombatant` вызывается), а не переключается выбор на труп.

## Критерии тестирования

- Новый тест в `src/ui/pages/CombatPage.test.tsx` (там уже есть смонтированные тесты на реальном
  компоненте для похожих сценариев — выбор токена и атака): смонтировать бой с одним живым и одним
  поверженным (`currentHp: 0`) бойцом на разных клетках, кликнуть по клетке поверженного —
  проверить, что вызывается `moveCombatant`, а не что изменился `selectedId` на труп.
- Отрицательная проба: без починки тест должен падать (клик выбирает труп). Убедиться, вернуть
  починку.
- `$GATES_CMD` (`npm run gate`) зелёный целиком.
