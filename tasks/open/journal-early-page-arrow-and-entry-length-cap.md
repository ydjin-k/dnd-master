# journal-early-page-arrow-and-entry-length-cap

Размер: XS. Зона: `journal`. Роль-исполнитель — `ui-developer` (см. `gamestudio/roles/ui-developer.md`
и `roles/_common.md`).

## Контекст — два отдельных уточнения от владельца продукта после `journal-hard-3-per-page-revert`

1. Стрелка перелистывания сейчас появляется только когда создана **7-я** запись (то есть уже
   существует второй разворот) — `src/ui/pages/JournalPage.tsx`, `<nav className="journal-page__
   pagination">` рендерится по условию `spreadCount > 1`, а `spreadCount =
   Math.max(1, Math.ceil(entries.length / 6))` даёт `1` при ровно 6 записях. Владелец хочет, чтобы
   стрелка появлялась уже при **6-й** записи — как только текущий разворот заполнен, а не когда уже
   есть куда листать.
2. Владелец подтвердил, что поле ввода записи не рассчитано на много текста — «пара предложений, не
   больше» — и хочет **убрать скролл** внутри записи (`journal-entry__text { max-height: 20rem;
   overflow-y: auto }`, добавлено в `journal-fixed-height-smart-pagination`), сохранив при этом
   гарантию, что гримуар не растягивается.

## Что нужно

1. **Ранняя стрелка**: заменить условие рендера `<nav className="journal-page__pagination">` с
   `spreadCount > 1` на условие «текущий разворот заполнен» — проще всего: `entries.length >= 6`.
   При ровно 6 записях `spreadCount` всё ещё будет `1` (совершенно верно — листать пока некуда), но
   стрелка «вперёд» уже видна, просто задизейблена существующей логикой
   `disabled={spreadIndex === spreadCount - 1}` (0 === 0 → задизейблена) — доп. правок в саму логику
   пагинации/дизейбла не требуется, только условие показа `<nav>`.
2. **Ограничение длины записи вместо скролла**: в `.journal-page__form textarea` добавить `maxLength`
   (константа рядом, например `JOURNAL_ENTRY_MAX_LENGTH`) — подобрать значение опытным путём в живом
   Tauri-приложении так, чтобы типичная запись «пара предложений» комфортно помещалась в фиксированную
   колонку разворота без необходимости скролла (ориентир — около 200-250 символов, но сверить
   визуально с реальным рендером трёх записей такой длины на одной колонке 520px высотой, не гадать
   на глаз). Рядом с textarea — короткая подсказка предела текстом (тот же паттерн, что уже применён
   к возрасту/золоту предыстории персонажа, `AGE_LIMIT`/`Math.min` в `characterCreationData.ts` —
   переиспользовать стиль подсказки, не саму функцию, она в другом модуле). Убрать
   `overflow-y: auto` из `.journal-entry__text` (визуальный скролл-бар больше не нужен, раз запись
   физически не может быть длиннее слота); `max-height: 20rem` можно оставить как чисто защитный
   `overflow: hidden` (без прокрутки, без скроллбара) на случай уже существующих в кампании старых
   более длинных записей (сохранённых до введения лимита) — это молчаливая подстраховка, не видимый
   элемент интерфейса.

## DoD

- При ровно 6 записях на развороте стрелка «вперёд» уже видна (задизейблена, пока некуда листать);
  на 7-й записи включается.
- Новая запись физически не может быть длиннее `JOURNAL_ENTRY_MAX_LENGTH` символов — предел показан
  текстом рядом с полем.
- Видимого скроллбара внутри записи больше нет; гримуар по-прежнему не растягивается ни при каких
  условиях (в т.ч. для старых сохранённых записей длиннее нового лимита — они молча обрезаются
  рамкой блока, не растягивая колонку).
- `$GATES_CMD` зелёный.

## Критерии приёмки

- Записать ровно 6 коротких записей — стрелка «вперёд» видна, но неактивна.
- Записать 7-ю — стрелка активна, открывает второй разворот.
- Попытаться ввести текст длиннее лимита — поле не даёт напечатать больше, рядом виден текст предела.
- Визуально: записи не показывают скроллбар, гримуар не меняет высоту.

## Критерии тестирования

- Тест: при `entries.length === 6` навигация пагинации рендерится (кнопка «вперёд» присутствует и
  задизейблена).
- Тест: `textarea` имеет `maxLength={JOURNAL_ENTRY_MAX_LENGTH}`.
- Существующие тесты `JournalPage.test.tsx` остаются зелёными.
