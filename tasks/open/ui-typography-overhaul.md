# ui-typography-overhaul

Размер: L

Зона: `ui-shell`. **НЕ ДИСПАТЧИТЬ без явного указания владельца** — карточка заведена по его просьбе
впрок, исполнение отложено на потом.

Роль-исполнитель — `ui-developer` (визуальное оформление вне зоны Developer, см.
`gamestudio/roles/ui-developer.md` и `roles/_common.md`), не `developer`.

## Контекст

Владелец продукта протестировал текущий текстовый вывод по всему приложению (карточки правил,
предысторий, персонажа и т.д.) и оценил его как «сырое», всё «сливается в одно» — не хватает
типографической иерархии и акцентов.

## Что нужно

1. **Читабельный, стилизованный шрифт** — «рисованный» (декоративный, в духе фэнтезийного
   оформления, уже упомянутого в GAME.md п.6 «фэнтезийное оформление интерфейса») для заголовков/
   акцентов, при этом основной текст остаётся легко читаемым (не заменять весь текст декоративным
   шрифтом — это обычно вредит читаемости длинных абзацев правил/описаний).
2. **Жирным шрифтом — навыки, свойства (особенности предыстории/расы/класса), названия предметов**
   по всему приложению, не точечно. Конкретный уже найденный пример: у каждой предыстории вторая
   характеристика (`feature` — особенность) сейчас идёт обычным текстом наравне с остальным —
   должна визуально выделяться (например, название особенности жирным, дальше обычным текстом
   описание — по образцу, как уже сделано у Послушника «Приют для верующих: ...», где «Приют для
   верующих» — это то, что нужно выделить).
3. Пройтись по всем экранам приложения (мастер персонажа, карточка персонажа, «Правила», бой,
   дневник, импорт) и применить эту типографику последовательно — не оставлять часть экранов в
   старом стиле.

## DoD

- Единый набор шрифтов/начертаний подключён и используется во всех разделах приложения (не
  разнобой между экранами).
- Навыки/свойства/особенности/названия предметов визуально выделены (жирным) везде, где они
  встречаются как отдельные значимые термины в тексте.
- `$GATES_CMD` зелёный, кадры/скриншоты приложены к отчёту (до/после), т.к. правка чисто визуальная
  и её нельзя оценить по коду.

## Критерии приёмки

- Владелец продукта смотрит вживую и подтверждает, что текст перестал «сливаться» — это
  единственный настоящий критерий приёмки для чисто визуальной карточки, автоматический тест тут
  ничего не докажет.
