# rules-spells-data

Размер: L

Зависимости: нет. Можно выполнять параллельно с `characters-name-suggestions-by-gender` (разные
зоны, разные файлы).

## Контекст

GAME.md п.3/п.1 требует, чтобы приложение отслеживало правила и состояние стола — заклинаний в
приложении пока нет вообще: ни данных, ни справочника (`CharacterWizard.tsx` прямо говорит игроку
«Списка заклинаний в приложении пока нет — заговоры и заклинания 1 уровня выбираешь сам по книге»).
У приложения нет системы получения уровней (`Character.level` нигде не меняется после создания), так
что **в этом батче нужны только заговоры (уровень 0) и заклинания 1-го уровня** — этого достаточно
для персонажа 1 уровня, которым всё в приложении сейчас и ограничено. Заклинания 2+ уровня — не
делать, не придумывать, не резервировать под них поля «на будущее».

Классы с заклинаниями уже на 1 уровне (см. `CLASS_SPELLCASTING_ABILITY` в
`src/ui/characterCreationData.ts`): Бард (`classes-bard`), Жрец (`classes-cleric`), Друид
(`classes-druid`), Чародей (`classes-sorcerer`), Колдун (`classes-warlock`), Волшебник
(`classes-wizard`). Только эти шесть классов должны фигурировать в поле `classes` заклинаний —
Следопыт/Паладин на 1 уровне заклинаний не получают, они уже осознанно исключены из
`CLASS_SPELLCASTING_ABILITY` по этой причине.

## Источник контента — обязательно к прочтению

Весь контент приложения — только открытый SRD 5.1 (см. правило в `GAME.md` «Система правил» и
приложение в целом). Существующий `src-tauri/rules/rules.json` целиком собран с
`https://longstoryshort.app/srd/` — русский перевод SRD 5.1 (переводчик cyborgsandmages,
CC BY-NC-SA 4.0, атрибуция уже есть внизу `RulesPage.tsx`). У этого же сайта есть раздел с
заклинаниями — найти его (структура остальных разделов подсказывает путь вида
`/srd/spells/...` или ссылку из общего оглавления SRD) и **брать текст оттуда же, тем же
способом**, каким уже собраны расы/классы/снаряжение. Ничего не выдумывать: если для какого-то поля
(например, точного типа урона у не-уронового заклинания) у источника нет значения — не заполнять его
фиктивным.

Если раздела заклинаний на сайте не найдётся вовсе — это стоп-сигнал, не повод брать текст из другого
источника (никаких dnd.su, fan-wiki, PHB-текста даже «для полноты») — сообщить об этом в отчёте
прямо, находка важнее тихого фолбэка.

## Что нужно

1. **Новый структурированный тип данных для заклинания** (не переиспользовать `RuleTopic`/`RuleBlock`
   — тем данным неудобно быть источником для будущего выбора заклинаний персонажем и их применения в
   бою, это разные карточки того же батчa, и факт «что за заклинание» должен жить в одном месте, а не
   дублироваться текстом внутри `RuleBlock`). Завести на обеих сторонах (TS `src/state/types.ts`,
   Rust `src-tauri/src/model.rs` или новый `src-tauri/src/spells.rs` — на усмотрение исполнителя, но
   в одном месте, не в двух конкурирующих структурах):
   ```
   Spell {
     id, name,
     level: 0 | 1,
     school: string,
     castingTime: string,
     range: string,
     components: string,        // как в источнике, напр. "В, С" или "В, С, М (клочок шерсти)"
     duration: string,
     concentration: bool,
     ritual: bool,
     classes: string[],         // подмножество ["classes-bard", ... "classes-wizard"] из шести выше
     description: string,       // полный текст описания заклинания из источника
     damageDice: string | null,       // если заклинание наносит урон костью — SRD-формат, напр. "1d10"
     damageType: string | null,       // напр. "огонь" — только если применимо
     attackRoll: bool,                // требует ли бросок атаки заклинанием (истина для лучевых атак)
     savingThrow: string | null,      // характеристика спасброска цели, если применимо ("Ловкость" и т.п.)
   }
   ```
   Поля `damageDice`/`damageType`/`attackRoll`/`savingThrow` нужны следующей карточке этого же
   батча (бой) — заполнять их честно по тексту источника; для заклинаний без урона/атаки/спасброска
   (утилитарные — «Свет», «Prestidigitation» и т.п.) оставлять `null`/`false`.

2. **Данные**: `src-tauri/rules/spells.json` — все заговоры и заклинания 1 уровня шести классов
   выше, каждое — один объект по схеме выше. Заклинание, доступное нескольким классам (обычная
   ситуация в SRD), — один объект с несколькими id классов в `classes`, не дублировать запись на
   класс.

3. **Загрузка**: новая Tauri-команда (по образцу `get_rules` в `src-tauri/src/rules.rs`/`lib.rs`) —
   `get_spells`, возвращает `Vec<Spell>`, зарегистрирована в `lib.rs`.

4. **Просмотр в разделе «Правила»**: `RulesPage.tsx` сейчас показывает разделы из `get_rules`
   (`RuleTopic`, категории вроде `races`/`classes`). Добавить в тот же экран (или отдельным блоком
   на нём) заклинания как ещё один просматриваемый раздел — своим форматированным видом (не через
   `RuleBlockView`, у заклинаний своя, более табличная форма: название, уровень/школа,
   время/дистанция/компоненты/длительность отдельной строкой, затем описание). Группировка минимум
   на «Заговоры» / «Заклинания 1 уровня» (плоский список из 60-90 пунктов в одном разделе неюзабелен
   — как именно группировать дальше, напр. по классу или алфавиту, на усмотрение исполнителя, это
   функциональная, не визуальная часть; вылизывание вида — не эта карточка и не эта роль).

## DoD

- `Spell`/`spells.json`/`get_spells` существуют и покрывают все заговоры + заклинания 1 уровня для
  Барда, Жреца, Друида, Чародея, Колдуна, Волшебника из найденного раздела источника — ни одного
  заклинания этих уровней для этих классов не пропущено (сверить количество с содержанием раздела
  источника, назвать число в отчёте: «N заговоров, M заклинаний 1 уровня»).
- Раздел «Правила» открывает и показывает заклинания, для каждого видно как минимум: название,
  уровень, школа, время сотворения/дистанция/компоненты/длительность, концентрация, ритуал, классы,
  полное описание.
- `$GATES_CMD` зелёный целиком.

## Критерии приёмки

- Открыть раздел «Правила» → найти заклинания → открыть заговор (например «Свет», если он есть у
  источника) и заклинание 1 уровня одного из шести классов — оба показывают полный текст без
  плейсхолдеров вида "TBD"/"???".

## Критерии тестирования

- Rust: тест, что `spells.json` парсится в `Vec<Spell>` без ошибок и непустой.
- Rust/TS: тест, что каждый элемент `classes` каждого заклинания — один из шести известных id классов
  (страховка от опечатки/левого класса).
