# characters-currency-denominations

Размер: L

**Диспатчить ПОСЛЕ того, как `characters-leveling-1-5` смержена в `skip-permissions-flag`** —
сильно пересекается по файлам (`CharacterWizard.tsx`, `CharactersPage.tsx`,
`characterCreationData.ts`, `model.rs`, `types.ts`) с левелингом, который на момент написания этой
карточки ещё в работе. Дождаться мержа, не дispatch-ить параллельно.

## Контекст

Сейчас деньги персонажа — одно число `gold: i64`/`c.gold`, всегда золотые монеты. Владелец продукта
хочет полноценную систему номиналов SRD 5.1, с возможностью указать/отследить деньги и в процессе
создания персонажа, и уже у готового.

Точный курс обмена — **сверено по `rules.json → equipment-coins`** (уже прочитано в этой сессии, не
перепроверять):

| Монета | в ММ (медных) |
|---|---|
| Медная (мм) | 1 |
| Серебряная (см) | 10 |
| Электрумовая (эм) | 50 |
| Золотая (зм) | 100 |
| Платиновая (пм) | 1000 |

Также по тому же источнику: «Стандартная монета весит 9 грамм... пятьдесят любых монет весят
полкилограмма или 1 фунт» — то есть **50 монет любого номинала = 1 фунт веса** (пригодится для
`characters-carrying-capacity`, если та карточка идёт следом — вес монет тоже считается в
грузоподъёмность по SRD, эта карточка должна оставить достаточно структурированные данные, чтобы
`characters-carrying-capacity` могла их использовать, не переизобретая).

## Что нужно

1. **Модель данных** (TS + Rust, `#[serde(rename_all = "camelCase", default)]`): заменить
   `gold: i64` на структуру монет — например `coins: { copper: i32, silver: i32, electrum: i32,
   gold: i32, platinum: i32 }` (или 5 плоских полей `copperCoins`/`silverCoins`/.../`platinumCoins`
   — на усмотрение исполнителя, главное чтобы каждый номинал был отдельным полем). **Миграция
   старых сохранений**: там, где раньше было `gold: number` (в золотых монетах) — конвертировать в
   `{ gold: oldValue, остальные: 0 }` при десериализации (тот же паттерн `#[serde(default)]` +
   отдельное поле под старое имя для совместимости, что уже применялся для предыдущих миграций
   персонажа — посмотреть на уже сделанные миграции age/gender/background в этом же файле как
   образец, не изобретать новый способ).
2. **Мастер персонажа**: там, где сейчас золото предыстории (`background?.gold`, custom background
   gold clamp до 30) — записывать в `gold` (в золотых монетах, как раньше), остальные номиналы 0. На
   шаге «Итог» дать возможность донастроить монеты вручную по каждому номиналу (5 полей вместо
   одного) — простые числовые инпуты, без сложного UI.
3. **Карточка персонажа**: показать все 5 номиналов с возможностью менять каждый по отдельности
   (кнопки +/− или числовые инпуты, по образцу уже существующей корректировки инвентаря/HP —
   переиспользовать тот же визуальный паттерн, не изобретать новый). Дополнительно показать одну
   строку «Итого» — суммарная стоимость в золотых эквивалентах (по курсу выше), чтобы не считать в
   уме.
4. Отрицательные значения по каждому номиналу не допускать (аналогично существующим клампам
   `Math.min(0, ...)`/`Math.max(0, ...)` у HP/ячеек заклинаний).

## DoD

- Персонаж хранит деньги по 5 номиналам (медь/серебро/электрум/золото/платина), не одним числом.
- Мастер персонажа позволяет донастроить монеты на шаге «Итог»; старт от золота предыстории работает
  как раньше (просто теперь это конкретно золотые монеты).
- Карточка персонажа показывает и позволяет менять каждый номинал, плюс суммарную оценку в зм.
- Старые сохранённые персонажи (с полем `gold: number`) корректно открываются — их золото становится
  золотыми монетами, остальные номиналы — 0.
- `$GATES_CMD` зелёный, включая тест на десериализацию старого JSON персонажа без новых полей монет.

## Критерии приёмки

- Создать персонажа с предысторией — золотые монеты равны золоту предыстории, остальные номиналы 0.
- В карточке персонажа добавить 5 серебряных и 3 медных монеты — счётчики обновляются по отдельности,
  «Итого» в зм пересчитывается верно (5 см = 0.5 зм, 3 мм = 0.03 зм).
- Открыть персонажа, сохранённого до этой карточки (со старым `gold: number`) — золотые монеты равны
  старому значению, остальные 0, приложение не падает.

## Критерии тестирования

- Тест на конвертацию курса (например 100 мм + 10 см + 1 эм + 1 зм + 1 пм = ожидаемая сумма в зм).
- Тест десериализации старого JSON персонажа (`gold: number`, без поля монет) — новый формат
  заполняется корректно.
