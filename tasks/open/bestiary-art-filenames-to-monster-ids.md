# bestiary-art-filenames-to-monster-ids

Размер: L. Зона: `combat` (бестиарий, данные). Роль-исполнитель — `developer`
(`gamestudio/roles/developer.md`) — это разбор и сопоставление данных, а не рисование.

## Контекст

Владелец продукта кладёт свой арт существ в `src-tauri/bestiary/images/` вручную. На диске сейчас
**439 файлов, из них в git только 51** — те, у кого есть монстр в `bestiary.json`. Остальные 388
ждут, пока до их монстров дойдут карточки (~250 существ SRD ещё не заведены).

**Владелец продолжает докладывать файлы** — набор растёт и будет расти дальше. Карточка обязана быть
пригодной к повторному запуску: то, что уже названо правильно, второй прогон не трогает.

## Правило имени — из README каталога, не выдумывать

`src-tauri/bestiary/images/README.md`: **имя файла = `id` существа** из `bestiary.json`, на который
ссылается поле `imageAsset`. Id латинские и происходят от английского имени SRD, а не от
транслитерации русского:

- `wolf.png` — Волк
- `bandit.png` — Разбойник
- `ape.png` — Обезьяна

То есть `Аболет.png` должен стать `aboleth.png`, а не `abolet.png`. **Транслитерация — это ошибка**,
которую легко сделать и трудно заметить.

## Две разные кучи, и работа с ними разная

1. **~150 файлов `ChatGPT Image <дата> (n).png`** — имя не несёт ничего. Монстр определяется
   **по самой картинке**: в этот арт вписан заголовок карточки с названием существа. Читать его
   глазами (инструмент чтения показывает изображение) — это проверенный способ, см.
   [[bestiary-image-matching-by-ocr]]. У проекта есть и свои OCR-модели
   (`src-tauri/models/*.rten`, подключены в `src-tauri/src/import.rs`) — можно опереться на них,
   если так надёжнее; способ на усмотрение исполнителя, важен результат.
2. **~238 файлов с русским названием** (`Аболет.png`, `Адская гончая.png`, `Анкилозавр.png`) —
   существо уже известно, нужна только сверка с английским именем SRD и переименование в `id`.

## Что нужно

1. Каждому файлу дать окончательное имя вида `<id>.<расширение>`, где `id` — латинский
   идентификатор существа SRD 5.1 по правилу README.
2. Собрать **манифест соответствия** и закоммитить его (текстовый файл в
   `src-tauri/bestiary/`): имя файла → русское название → английское имя SRD → `id`. Он нужен
   будущей карточке на ~250 монстров: она возьмёт из него готовое сопоставление вместо того, чтобы
   разбирать арт заново.
3. Файлы, чьё существо **не удалось опознать** или которого нет в SRD, — не переименовывать и не
   удалять, а перечислить в манифесте отдельным разделом с причиной. Их разберёт владелец.
4. Дубликаты (два файла на одно существо) — не выбирать «лучший» самостоятельно: оставить оба,
   назвать в манифесте, решение за владельцем.

## Решение по коммиту файлов — принято до написания карточки

**Переименованные картинки в git НЕ добавлять.** Коммитится только манифест.

Причина: 388 неотслеживаемых файлов весят около 1.1 ГБ, и добавление их в историю необратимо, а
пользы до появления монстров не даёт — сложившийся порядок в проекте другой: арт входит в git тогда,
когда существо заводится в `bestiary.json` (сейчас там ровно 51 файл на 50 монстров). Манифест
маленький, versionable и переживает любую переустановку, поэтому работа не потеряется, даже если
файлы останутся только на диске владельца.

Если владелец решит иначе — это отдельное решение и отдельный коммит, не часть этой карточки.

## Границы (запреты, не пожелания)

- **Ничего не удалять** из `src-tauri/bestiary/images/`. Ни дубликаты, ни неопознанное, ни то, что
  кажется мусором. Это авторский арт владельца, и он единственный экземпляр.
- **Не транслитерировать** русское название в id (см. выше).
- **Не трогать `bestiary.json`** и не заводить в нём новых существ — это другая, ещё не написанная
  карточка. Здесь только имена файлов и манифест.
- **Не скачивать картинки из сети** и не генерировать недостающие — README прямо запрещает.
- Уже правильно названные файлы не переименовывать повторно.

## Как поступить, если не успеваешь за одну сессию

Сначала куча 2 (русские имена — быстрее и без чтения картинок), затем куча 1. Манифест дописывать по
ходу, а не в конце: прерванная сессия должна оставить пригодный результат. В отчёте назвать, сколько
файлов разобрано и сколько осталось.

## DoD

- Каждый разобранный файл назван по `id` SRD-существа.
- Манифест закоммичен и покрывает все файлы каталога, включая неопознанные и дубликаты.
- Ни один файл не удалён и не перезаписан: число файлов в каталоге до и после совпадает.
- `$GATES_CMD` зелёный (код не менялся, но прогон обязателен).

## Критерии приёмки

- В каталоге не осталось файлов с именем `ChatGPT Image…`, кроме перечисленных в манифесте как
  неопознанные.
- Выборочно: взять 5 переименованных файлов, открыть их и убедиться, что существо на картинке
  соответствует имени файла.
- Число файлов в каталоге до и после совпадает.

## Критерии тестирования

- Проб на имена файлов не заводить: это разовая курация данных, а не поведение программы.
- Если по ходу обнаружится, что какой-то уже закоммиченный файл назван неверно (существо на картинке
  не то), — назвать в отчёте отдельно: это будет означать, что монстр в `bestiary.json` показывает
  чужую картинку, и чинится он уже как дефект.
