# soundboard-tab

Размер: L. Зона: `audio` (звуки и музыка) + новая вкладка (значит немного `ui-shell`: пункт нав-меню и
общий хедер `AppShell.tsx`). Роль-исполнитель — `developer` (данные + новая вкладка — логика/показ, не
внешний вид, `gamestudio/roles/developer.md`).

## Контекст

Владелец продукта загрузил собственную (авторскую, не стороннюю) коллекцию атмосферной музыки и
эмбиент-звуков для использования во время игры — «саундборд» для мастера. Ассеты уже лежат в дереве и
уже переименованы Producer'ом в латиницу с понятной структурой (были на кириллице с пробелами —
переименовано для целостности с остальными файлами в `public/audio/`):

```
public/audio/soundtrack/
├── battle/        battle.mp3, iron.mp3, steel.mp3, last-stand-of-oakhaven-2.mp3, the-oath.mp3
├── tavern/        dance.mp3, festival.mp3, quiet-hour.mp3, last-stand-of-oakhaven.mp3,
│                  tavern-music.mp3, taverns-dance.mp3
├── travel/        long-road.mp3, steps.mp3, the-quiet-road-1.mp3, the-quiet-road-2.mp3,
│                  road-to-the-whispering.mp3
└── ambient/
    ├── wind/      cave-wind.mp3, desert-storm-wind.mp3, gusting-wind.mp3, wind.wav
    ├── rain/      rain-with-thunder.mp3, light-rain.mp3, heavy-rain.mp3
    ├── campfire/  village.mp3, campfire.mp3, night-campfire.mp3
    ├── forest/    night-forest.mp3, birdsong.wav, stream.wav, morning-forest.wav
    ├── sea/       sea.mp3
    └── cave/      moving-slab.mp3, dripping-water.mp3, cave-draft.mp3, dungeon-draft.mp3
```

`battle/`, `tavern/`, `travel/` — мелодическая музыка (одна тема играет за раз, как трек-лист).
`ambient/*` — зацикленные фоновые звуки природы/окружения, задуманы для **одновременного** наложения
друг на друга и на музыку (например, музыка таверны + костёр одновременно). Схема названий: русские
подписи в интерфейсе (Бой/Таверна/Путешествия, Ветер/Дождь/Костёр/Лес/Море/Пещера), латинские пути к
файлам — уже так и лежит на диске, только сматчить один к одному.

Этот функционал не был описан заранее в `GAME.md` — фича обсуждена и согласована с владельцем в этой
сессии, не выдумана исполнителем.

**Ключевое архитектурное требование, ради которого стоит вся карточка**: воспроизведение обязано
переживать переключение вкладки. Мастер запускает музыку/эмбиент, уходит на вкладку «Бой» вести
сражение — звук не должен обрываться. Смотри `src/App.tsx` — `AppShell`-компонент уже устроен так, что
`<header>` рендерится СНАРУЖИ `children(tab)` (переключается только `<main>`), т.е. состояние кампании
(`CampaignContext`/`CampaignProvider`, см. `src/state/CampaignContext.tsx`) уже живёт выше свитча
вкладок по этому же принципу — **повторить этот же паттерн**: завести свой контекст (например
`SoundtrackContext`/`SoundtrackProvider`, тот же файл-стиль, что `CampaignContext.tsx`), смонтировать
его в `App.tsx` НАД `AppShell`/`AppContent`, а не внутри новой страницы — тогда `<audio>`-элементы не
демонтируются при уходе со вкладки.

## Что нужно

1. Новая вкладка **«Саундборд»** — добавить в `Tab` (`src/ui/AppShell.tsx`), в список `TABS`, в
   `switch` в `src/App.tsx`, значок в `UIIcon` (по образцу уже существующих — растр для новых значков
   умеет только `codex`/UI Developer, но здесь можно и текстовым/векторным значком в едином стиле
   существующих, если не требуется PNG-арт; если решишь, что нужен растровый значок — не рисуй сам,
   назови это отдельной строкой в отчёте для передачи UI Developer'у).
2. Контекст/провайдер аудио-состояния (см. архитектурное требование выше) — какие треки сейчас играют,
   громкость каждого, play/pause. Один канал «музыка» (играет один трек за раз, выбор нового трека
   останавливает предыдущий), и независимый набор каналов «эмбиент» (несколько луп-треков одновременно,
   каждый свой play/stop/громкость).
3. Страница «Саундборд»: список по категориям (как в дереве выше, русские подписи), у каждого
   трека — play/pause и слайдер громкости. Эмбиент-треки зациклены (`loop`); музыкальные треки тоже
   зацикливаются посуточно (не единый проигрыш — фон должен звучать всё время сессии, не обрываться
   через 3 минуты).
4. Компактный индикатор «сейчас играет» в `app-shell__header` (там же, где кампания/переключение
   кампании) — что играет + быстрая кнопка остановить, доступная с ЛЮБОЙ вкладки, не только со
   страницы «Саундборд».
5. Общая громкость/мьют не обязательны в этой карточке, если не мешает базовому сценарию — можно
   оставить на будущую доработку (не выдумывай лишний функционал сверх сказанного).

## Что не нужно

- Не трогать существующие короткие UI-звуки (`playLimitSound`, клики, кубики и т.д., `uiSounds.ts`) —
  это отдельная система, не смешивать с этой.
- Не переименовывать и не трогать `public/audio/Звук магии.mp3` — отдельный несвязанный файл, не часть
  этой коллекции (владелец загрузил его раньше и отдельно, по нему может быть отдельная карточка).
- Не проектировать сохранение выбора между запусками приложения (localStorage/бэкенд) — не просили,
  делать не нужно, если не окажется тривиальным побочным следствием контекста.

## DoD

- Вкладка «Саундборд» видна в навигации, по клику показывает все категории и треки списком.
- С любой вкладки видно, что сейчас играет (если играет), и можно остановить одним кликом не уходя со
  страницы.
- Переключение вкладки (в т.ч. во время боя) не останавливает и не перезапускает уже играющий
  трек/эмбиент.
- Можно одновременно играть один музыкальный трек и один-два эмбиент-трека без взаимных обрывов.
- `$GATES_CMD` зелёный.

## Критерии приёмки

- В живом Tauri-окне: включить трек из «Таверна», перейти на «Бой», подождать — музыка продолжает
  играть, индикатор в хедере это показывает; остановить прямо из хедера, не возвращаясь на вкладку
  «Саундборд».
- Включить одновременно музыку и 1-2 эмбиент-трека (например, «Костёр» + «Дождь») — оба звучат
  одновременно, регулировка громкости одного не глушит другой.
- Переключить музыкальный трек на другой, пока играет первый — первый останавливается, играет только
  новый (эмбиент при этом не трогается).

## Критерии тестирования

- Юнит/компонентный тест на сам факт немонтирования страницы «Саундборд» без остановки
  воспроизведения (контекст переживает размонтирование потребителя) — это и есть архитектурный риск
  карточки, тест обязан описывать именно его, а не просто рендер списка.
- Если тестовое окружение не умеет реальный `<audio>`/`HTMLAudioElement` — замокать по образцу, как
  уже сделано для звуков в проекте (`uiSounds`/`playLimitSound` в существующих тестах), не пропускать
  сценарий целиком.

## На заметку Producer'у при приёмке

Суммарный вес новой коллекции ощутимый (несколько `.wav` по 40+ МБ) — если после мержа `INSTALL_CMD`/
сборка/запуск дев-сервера заметно потяжелеют, стоит отдельным решением обсудить с владельцем конвертацию
крупных `.wav` в `.mp3` (не в этой карточке и не по инициативе исполнителя).
