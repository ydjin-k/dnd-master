# section-theming-and-welcome

Размер: L

Зона: `ui-shell`. Роль-исполнитель — `ui-developer` (см. `gamestudio/roles/ui-developer.md` и
`roles/_common.md`), не `developer`. Дождаться, пока `characters-sheet-and-wizard-cleanup` смёржена —
эта карточка трогает общий `theme.css`/`AppShell.css`, конфликтовать с точечными правками той
карточки не нужно.

## Контекст

После направления «Лунный арканум» (`ui-visual-and-sound-polish`) владелец продукта считает
приложение однотипным — один и тот же плоский стиль на все разделы. Хочет, чтобы каждый раздел
(Приключение/Бой/Кубики/Персонажи/Дневник/Правила/Бестиарий) имел свою цветовую/тематическую нотку в
рамках общего фэнтезийного стиля игры, отдельно — редизайн приветственного экрана (`Launcher.tsx`,
«лицо приложения»), и несколько вариантов звука клика по кнопке на прослушку взамен нынешнего
(«неплохой, но глуховатый»).

**Это carточка «сначала предложить»** (см. `roles/ui-developer.md → Владеет → Инициатива»`) — только
докладывает в `docs/art/inbox/`, не трогает production-код без явного согласия следующим шагом.

## Что нужно

### 1. Тематизация разделов

Для каждого из 7 разделов — краткое предложение (не полный макет каждого экрана, а направление):
акцентный цвет/оттенок в рамках уже принятой тёмной палитры «Лунного арканума» (не менять базовый
фон/тёмную основу — трогать акценты, рамки, подсветку активного пункта раздела, иконку раздела),
1-2 предложения, что отличает раздел визуально (например: «Бой» — более резкие/угловатые акценты и
красноватый тон vs «Дневник» — тёплый пергаментный тон, который уже определён в `journal-polish`, если
она смёржена раньше — свериться и не предлагать для Дневника второе несовместимое направление).
Файл-описание + примеры (SVG-иконка раздела/цветовой чип) в `docs/art/inbox/section-themes.md` +
по одному файлу-примеру на раздел.

### 2. Приветственный экран (`Launcher.tsx`)

2-3 варианта редизайна (не текущий голый список кампаний на тёмном фоне) — макеты в
`docs/art/inbox/` (`launcher-variant-a...`, `-b...`, возможно `-c...`), с кратким описанием каждого.

### 3. Варианты звука клика на прослушку

Текущий `playButtonClickSound` (`src/audio/uiSounds.ts`) описан как «неплохой, но глуховатый».
Подготовить 3-4 синтезированных варианта (разный тембр/яркость/длина — не косметические вариации
одного и того же), и **самостоятельную HTML-страницу** для прослушки: одна страница
(`docs/art/inbox/click-sound-variants.html`), кнопка на каждый вариант, при нажатии проигрывает этот
вариант через Web Audio API (тот же принцип синтеза, что уже есть в `uiSounds.ts` — просто несколько
кандидатов рядом, без внешних файлов, без сборки всего приложения ради прослушки). Владелец открывает
файл и кликает по кнопкам, чтобы сравнить.

## DoD

- `docs/art/inbox/section-themes.md` + примеры на каждый из 7 разделов.
- 2-3 варианта `Launcher.tsx` в `docs/art/inbox/`.
- `docs/art/inbox/click-sound-variants.html` — самостоятельно открывается в браузере, каждая кнопка
  реально проигрывает свой вариант звука.
- Production-код (кроме файла звуковых вариантов, который не подключён к приложению) не тронут — это
  предложение, не реализация.

## Критерии приёмки

- Открыть `docs/art/inbox/click-sound-variants.html` в браузере напрямую (двойным кликом или
  `file://`) — работает без запуска всего приложения, каждая кнопка звучит по-своему.
- Каждый из 7 разделов имеет узнаваемо своё предложение по акценту, не одна и та же палитра под
  разными подписями.

## Критерии тестирования

Не применимо — карточка не меняет production-код, автотесты не нужны.
