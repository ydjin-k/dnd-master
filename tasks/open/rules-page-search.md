# rules-page-search

Размер: M

## Что нужно

Владелец продукта: раздел «Правила» (`RulesPage.tsx`) нужен поиск — сейчас навигация только по
дереву категорий/тем слева, найти конкретную вещь (например, конкретный инструмент или набор
снаряжения) можно только пролистав вручную. Заодно проверить: контент про наборы и инструменты
(«Инструменты», категория `equipment` → `equipment-tools`) уже ЕСТЬ в `rules.json` (таблица цен/веса
+ абзацы описаний по некоторым наборам, например «Набор для грима») — это не пропавший контент, а
вопрос находимости, поиск должен решить проблему сам по себе. Если по факту какие-то конкретные
инструменты/наборы упоминаются в таблице, но не имеют развёрнутого абзаца-описания в источнике —
это соответствует исходнику (не каждая позиция таблицы SRD имеет отдельный абзац) и фиксировать
отдельной находкой, не выдумывать описание.

Добавить строку поиска над/рядом с навигацией `RulesPage.tsx`:

- Фильтрует список тем слева по совпадению в `title` (простой case-insensitive substring, без
  полнотекстового поиска по `blocks` в этой карточке — это заведомо большая отдельная задача, не
  делать её здесь неявно).
- Также фильтрует заклинания (`get_spells`, уже подключены в этом же экране после карточки
  `rules-spells-data`) по `name`.
- Пустой запрос — показывает всё как сейчас.
- Заодно (по тому же принципу «выборы вместо голого текста», уже применённому в проекте) — если по
  запросу совпадает ровно один результат, можно сразу открыть его — не обязательно, на усмотрение
  исполнителя.

## DoD

- Поле поиска в «Правилах» реально фильтрует список тем/заклинаний по вводу.
- `$GATES_CMD` зелёный.

## Критерии приёмки

- Реальный сценарий: открыть «Правила», ввести «инструмент» — среди прочего видно тему
  «Инструменты»; ввести название конкретного заговора — видно его в списке заклинаний.

## Критерии тестирования

- Тест в `RulesPage.test.tsx` (или новый, если файла ещё нет): ввод в поле поиска сокращает список
  видимых тем до совпадающих по названию.
