# journal-pagination-and-layout-cleanup

Размер: M. Зона: `journal`. Роль-исполнитель — `ui-developer` (см. `gamestudio/roles/ui-developer.md`
и `roles/_common.md`).

## Контекст

Владелец продукта протестировал разворот книги из `journal-book-spread-and-dice-overlap-fix` —
концепция понравилась («выглядит неплохо»), но интерфейс требует доводки. Пять отдельных замечаний
по `src/ui/pages/JournalPage.tsx`/`.css`:

1. Заголовок «Дневник путешествий» (`<h2>`, абсолютно спозиционирован сверху) налезает на сам
   гримуар — визуально конфликтует с художественным оформлением обложки/страниц, а не аккуратно
   венчает разворот.
2. «Записей пока нет.» (`.journal-page__empty`, сейчас `grid-column: 1 / -1` — растянут по центру
   через обе страницы) выглядит некрасиво по центру — перенести на левую страницу разворота (не
   растягивать на обе колонки).
3. **Пагинация**: сейчас все записи выводятся одним списком в 2 колонки без ограничения. Сделать по
   3 записи на каждой странице разворота (3 слева + 3 справа = 6 на разворот), а когда записей
   больше — появляется возможность перелистнуть на следующий разворот. `entries` уже отсортирован
   новыми сверху (`entries.sort((a, b) => b.timestamp.localeCompare(a.timestamp))`, `JournalPage.tsx`
   строка 25) — при добавлении новой записи она попадает в начало массива, поэтому после сохранения
   новой записи стоит сбрасывать текущую страницу разворота на первую (нулевую), чтобы новая запись
   сразу была видна.
4. **Звук перелистывания**: `public/audio/page-flip.mp3` уже лежит в репозитории (загружен
   владельцем продукта) — проигрывать его при переходе на другую страницу разворота, тем же
   паттерном, что `quill-scratch.mp3` в `handleSubmit` (`new Audio(...)`, `audio.currentTime = 0`,
   `void audio.play().catch(() => undefined)`).
5. Поле «Что произошло?» (`textarea` + кнопка «Записать» в `.journal-page__form`) сейчас расположено
   внутри самого гримуара (справа, `width: calc(50% - ...)`) — вместе со страницами это выглядит
   «всё навалено в кучу». Вынести форму **за пределы визуального гримуара** — под него (и, по
   желанию, сдвинутую влево, а не на всю ширину) — как отдельный элемент интерфейса под книгой, не
   часть страниц разворота.
6. Кнопка удаления записи (`.journal-entry__remove`) на hover сейчас показывает рамку + полупрозрачный
   фон (`border-color`/`background` в `:hover`, `JournalPage.css`) — владелец продукта считает, что
   это выглядит как лишний «квадратный прозрачный контур». Убрать рамку и фон из hover-состояния,
   оставить **только смену цвета текста** на `var(--dm-danger)` при наведении; клик по-прежнему
   удаляет запись (`removeJournalEntry` не трогать).

## Что нужно

- П.1: переработать позиционирование/оформление `.journal-page h2`, чтобы заголовок читался как
  чистая надпись над разворотом, не наслаиваясь на текстуру обложки/корешка — визуально сверить в
  живом Tauri-приложении (jsdom этого не покажет).
- П.2: `.journal-page__empty` — убрать `grid-column: 1 / -1`, разместить в пределах левой колонки
  (`grid-column: 1`), выровнять по левому краю страницы (не по центру всего разворота).
- П.3-4: добавить состояние текущей страницы разворота в `JournalPage.tsx` (`useState(0)`), нарезать
  отсортированный `entries` на группы по 6 (3+3), рендерить только текущую группу; при
  `entries.length > 6` показать управление «вперёд/назад» (кнопки, доступные с клавиатуры,
  задизейбленные на границах диапазона) — стилистика на усмотрение `ui-developer`, в духе
  остального оформления книги (например, уголки страниц или простые стрелки у корешка). При
  успешном добавлении записи (`handleSubmit`) — сбросить состояние страницы на `0`. Проигрывать
  `page-flip.mp3` по нажатию кнопки перелистывания.
- П.5: переместить `<form className="journal-page__form">` за пределы `<div className="journal-page">`
  (сделать сиблингом ниже, не внутри контейнера с художественным оформлением обложки) и
  соответствующим образом переработать CSS — сейчас там `width: calc(50% - ...); margin-left: auto`,
  подгонявшее её под правую страницу; вне гримуара это уже не нужно, оформить как отдельный
  элемент (может быть уже, полной ширины или сдвинут влево — на усмотрение, лишь бы не наслаивался
  на страницы).
- П.6: `.journal-entry__remove:hover` — оставить только `color: var(--dm-danger)`, убрать
  `border-color`/`background` (или явно вернуть их в `transparent`/`none`, как в состоянии покоя).

## DoD

- Заголовок не перекрывает художественное оформление обложки/корешка.
- Пустое состояние — на левой странице, не растянуто по центру разворота.
- Разворот показывает максимум 6 записей (3+3); при большем числе есть рабочее перелистывание со
  звуком `page-flip.mp3`; новая запись после сохранения видна сразу (страница сброшена на первую).
- Форма добавления записи находится визуально вне гримуара, под ним.
- Наведение на «×» удаления меняет только цвет текста на красный, без рамки/фона.
- Существующая функциональность (добавление/удаление записи, автосохранение, мобильная адаптация)
  без регрессий.
- `$GATES_CMD` зелёный.

## Критерии приёмки

- Добавить 7+ записей — видно ровно 6 на первом развороте (3+3), кнопка «вперёд» открывает
  следующие со звуком перелистывания; на последней странице кнопка «вперёд» недоступна.
- С пустым дневником текст «Записей пока нет.» — на левой странице, не по центру.
- Открыть дневник — заголовок аккуратно венчает разворот, не наслаивается на текстуру.
- Форма записи — явно отдельный блок под гримуаром, не внутри его страниц.
- Навести на «×» — текст краснеет, никакой рамки/квадрата вокруг не появляется.

## Критерии тестирования

- Тест на пагинацию: рендер >6 записей показывает только 6, кнопка «вперёд» переключает на
  следующую группу, кнопка недоступна на границах диапазона.
- Тест, что добавление новой записи сбрасывает страницу на первую (запись видна без ручного
  перелистывания назад).
- Существующие тесты `JournalPage.test.tsx` (добавление/удаление/пустое состояние) остаются зелёными
  с поправкой мест, куда переехала разметка (форма вне `.journal-page`, если тест ищет её через
  `closest`/структуру DOM).
