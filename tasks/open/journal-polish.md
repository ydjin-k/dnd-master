# journal-polish

Размер: S

Зона: `ui-shell`. Роль-исполнитель — `ui-developer` (см. `gamestudio/roles/ui-developer.md` и
`roles/_common.md`), не `developer`.

## Контекст

Владелец продукта: раздел «Дневник» в целом хорош, но запись нельзя удалить, поле ввода слишком
большое, и раздел стоит оформить тематически (по образу пергамента/бумаги — это раздел про записи
путешествий), со звуком пишущего пера после сохранения записи.

## Что нужно

### 1. Удаление записи

`CampaignContext.tsx` уже даёт паттерн: `addJournalEntry` — просто фильтрует/дописывает массив
`state.journal` и зовёт общий `persist(next)` (не отдельная бэкенд-команда). Добавить туда же
`removeJournalEntry(id: string)` тем же способом (`persist({ ...state, journal: state.journal.filter(e => e.id !== id) })`),
прокинуть через контекст. В `JournalPage.tsx` — крестик/кнопка удаления у каждой записи
(`journal-entry`), вызывающая `removeJournalEntry(entry.id)`.

### 2. Поле ввода — компактнее

`<textarea rows={3}>` в `.journal-page__form` сейчас занимает много места. Уменьшить (меньше строк по
умолчанию, ширина под реальный текст, а не на всю ширину раздела) — запись всё ещё может расти при
вводе длинного текста, но по умолчанию не должна быть гигантской.

### 3. Тематическое оформление — пергамент

Визуально оформить `.journal-page` в духе пергамента/старой бумаги (текстура/цвет фона под пергамент,
рамка как у старого документа, шрифт записей — уже есть декоративный/тематический шрифт из
`ui-typography-overhaul`, использовать его для оформления, не изобретать новый с нуля). Не ломать
читаемость длинных записей ради стиля — стиль должен быть у рамки/фона/акцентов, не у обычного текста
записи, который остаётся легко читаемым (тот же принцип, что уже был в `ui-typography-overhaul` про
декоративный vs основной шрифт).

### 4. Звук записи

После успешного `handleSubmit` (запись реально сохранена, `addJournalEntry` завершился) — короткий
звук «пишущего пера по бумаге» (шуршащий/скрипящий, синтезировать в коде через Web Audio API, тем же
способом, что и остальные звуки интерфейса — `src/audio/uiSounds.ts`, без внешнего файла, если
владелец продукт отдельно не пришлёт свой; звук клика по кнопке «Записать» из общего обработчика
кнопок остаётся как есть, это ДОПОЛНИТЕЛЬНЫЙ отдельный звук после реального сохранения, а не замена).

## DoD

- У каждой записи дневника есть способ её удалить, реально убирающий запись из `state.journal`.
- Поле ввода компактное по умолчанию.
- Раздел визуально оформлен как пергамент/старая бумага, текст записей легко читается.
- После сохранения записи звучит отдельный звук «пера».
- `$GATES_CMD` зелёный.

## Критерии приёмки

- Добавить запись — появляется в списке, звучит звук пера (помимо обычного клика кнопки).
- Нажать удаление у любой записи — она пропадает из списка и не появляется заново после перезахода в
  раздел (реально сохранено, не только в памяти React).

## Критерии тестирования

- Тест на `removeJournalEntry`: вызывает `persist` с массивом без удалённой записи (мокнутый
  `persist`/бэкенд, по образцу существующих тестов `CampaignContext`/`JournalPage`).
- Тест, что кнопка удаления в `JournalPage.tsx` вызывает `removeJournalEntry` с верным `id`.
