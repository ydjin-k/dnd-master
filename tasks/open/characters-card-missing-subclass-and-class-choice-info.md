# characters-card-missing-subclass-and-class-choice-info

Размер: L. Зона: `characters`, файлы `src/ui/pages/CharactersPage.tsx` / `src/ui/CharacterWizard.tsx` /
`src/ui/characterCreationData.ts`. Роль-исполнитель — `developer` (показ/состояние — зона Developer,
не UI Developer, см. `gamestudio/roles/developer.md`).

## Контекст

Владелец продукта протестировал вживую и сообщил: у Колдуна с покровителем Архифеей на «Итоге» не
видно, что покровитель даёт дополнительные заклинания. У Следопыта не видно, что даёт «Известная
местность» и «Избранный враг» («Знание заклятого врага» — видимо, то же самое, что «Избранный
враг», владелец мог перепутать название). **Владелец прямо говорит: уверен, что похожая проблема
есть у всех классов и подклассов** — значит, нужен не точечный патч этих двух примеров, а аудит
всего механизма показа выборов класса/архетипа персонажа, начиная с этих двух подтверждённых
находок.

### Находка 1 (подтверждена в коде) — поля Следопыта нигде не показываются после создания

`favoredEnemy`/`knownTerrain` (выбор «Избранный враг»/«Известная местность» у Следопыта) —
захватываются в `CharacterWizard.tsx` (используются на шаге «Итог» самого визарда, строки ~881,
894, 1520 — там показываются) и сохраняются в `Character`, но **`CharactersPage.tsx` их не
рендерит вообще ни в одном месте** (проверено — ноль упоминаний `favoredEnemy`/`knownTerrain` в
файле). Из-за этого выбор виден один раз, в момент создания персонажа на «Итоге» визарда, а потом
пропадает из вида навсегда — на самой карточке персонажа в списке этой информации нет.

### Находка 2 (вероятная, требует подтверждения воркером) — блок класса/архетипа может целиком не
рендериться

`CharactersPage.tsx`, блок `<details className="character-card__class-features">` (строка ~951-1077)
рендерится только при условии `classFeatures.length > 0 || classResources.length > 0 ||
classScaling.length > 0`. Внутри этого блока показываются и другие гранты архетипа — `domainSpells`
(заклинания архетипа, строка ~1056), `subclassScaling` (строка ~1022), `grants?.bonusCantrips`
(~1043), `grants?.damageResistances` (~1040), `healingBonus` (~1049) — но ни один из них **не входит
в условие открытия блока**. Если у архетипа на конкретном уровне персонажа нет ни одной
классовой/архетипной особенности текстом (`classFeatures`), ни классового ресурса
(`classResources`), ни классового скейлинга (`classScaling`) — весь блок не рендерится вообще, и
эти гранты остаются невидимыми, даже если у самого архетипа есть, например, только `spellsByLevel`
или только `scaling`. Для Архифеи это не должно было сработать (у неё есть 2 текстовые
`featuresByLevel[1]` записи, значит `classFeatures.length > 0` и блок должен открыться) — **воркеру
нужно самому воспроизвести живьём** (создать Колдуна с Архифеей в приложении, посмотреть карточку
персонажа и «Итог» визарда) и разобраться, почему владелец всё равно не увидел заклинания архетипа,
а не полагаться на этот анализ без проверки.

## Что нужно

1. **Воспроизвести обе жалобы живьём** в Tauri-приложении (создать Колдуна/Архифею, создать
   Следопыта с выбором врага/местности) и точно определить, где теряется информация — на «Итоге»
   визарда, на карточке персонажа в списке, или в обоих местах.
2. **Показать `favoredEnemy`/`knownTerrain` на карточке персонажа** (`CharactersPage.tsx`) — не
   только в визарде при создании. Формат — по образцу уже существующих строк-грантов
   (`character-card__prof` и т.п.).
3. **Починить условие открытия блока классовых особенностей**, если находка 2 подтвердится —
   добавить в условие все грант-виды, которые могут отрендериться внутри блока (`domainSpells`,
   `subclassScaling`, `grants?.bonusCantrips`, `grants?.damageResistances`, `healingBonus`,
   `subclassOptions`/`resourceOptions` и т.п.), чтобы блок открывался, если есть хоть что-то, что он
   должен показать.
4. **Аудит по всем 36 архетипам (12 классов)**, не только по двум примерам из жалобы: пройти по
   каждому классу, создать персонажа каждого класса в приложении (или хотя бы прогнать через
   существующие тесты + выборочную живую проверку на нескольких показательных классах — полный
   живой прогон всех 36 может не влезть в одну сессию, см. «Как поступить, если не успеваешь»),
   убедиться, что все гранты архетипа (заклинания, скейлинг, ресурсы, владения, сопротивления,
   бонусные заговоры, владения инструментами) и все выборы базового класса (не только у Следопыта —
   проверить, нет ли других классов с похожими «выбор при создании, не хранится видимым текстом на
   карточке» полями) видны и на «Итоге» визарда, и на карточке персонажа после создания.

## Как поступить, если не успеваешь за одну сессию

Если полный живой прогон всех 36 архетипов не влезает — обязательно подтвердить и починить два
конкретных случая из жалобы (Архифея, Следопыт) и общую причину (пункт 3), затем **живьём
проверить хотя бы 5-6 архетипов разных типов** (с одними только заклинаниями, с одним только
scaling, с одним только resourceOptions, с одними только владениями/сопротивлениями — по одному
представителю каждого вида гранта) как выборку, подтверждающую, что общая причина найдена и
устранена, а не просто два патча под конкретные классы. В отчёте явно перечислить, какие архетипы
проверены живьём, какие — только по коду/тестам.

## DoD

- Оба сообщённых случая (Архифея, Следопыт) воспроизведены, причина найдена и описана в отчёте, не
  просто предположена.
- `favoredEnemy`/`knownTerrain` видны на карточке персонажа Следопыта.
- Все виды грантов архетипа, которые уже умеет вычислять код (`domainSpells`, `subclassScaling`,
  `bonusCantrips`, `damageResistances`, `healingBonus`, `resourceOptions` и т.п.), видны на карточке
  персонажа независимо от того, есть ли у архетипа отдельно текстовые `classFeatures`.
- `$GATES_CMD` зелёный.

## Критерии приёмки

- Создать Колдуна с покровителем Архифеей — на «Итоге» визарда и на карточке персонажа в списке
  видны заклинания, которые даёт покровитель.
- Создать Следопыта, выбрать врага и местность — оба выбора видны на карточке персонажа в списке
  (не только на «Итоге» визарда при создании).
- Пройтись по нескольким другим архетипам (см. выборку выше) — гранты видны везде, где должны быть.

## Критерии тестирования

- Тест: карточка персонажа Следопыта с заданными `favoredEnemy`/`knownTerrain` рендерит оба значения
  текстом.
- Тест на новое условие открытия блока классовых особенностей: архетип, у которого есть только
  `spellsByLevel` (или только `scaling`, или только `resourceOptions`) и нет `featuresByLevel`/
  `classResources`/`classScaling`, всё равно открывает блок и показывает свой грант — отрицательная
  проба (без гранта блок не рендерится / рендерится пустым) обязательна.
- Существующие тесты `CharactersPage.test.tsx`/`CharacterWizard.test.tsx`, завязанные на текущее
  поведение этих блоков, поправить под новое.
