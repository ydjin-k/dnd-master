# build-gates-run-cargo-test

Размер: S. Роль: Developer. Зона: `engine`. Предусловие: нет.

## Зачем — дыра подтверждённая, а не теоретическая

Ворота проекта сегодня такие (`package.json:13`):

```
"gate": "npm run typecheck && npm test && npm run build && cargo check --manifest-path src-tauri/Cargo.toml"
```

Последний шаг — **`cargo check`, а не `cargo test`**. Он компилирует, но **не запускает ни одной
Rust-пробы**. Значит `$GATES_CMD` может быть зелёным при красной Rust-пробе, и воркер, честно
отчитавшийся «ворота прошли», про поломку не узнает.

Это выстрелило дважды за один день, 16-17.09.2026:

1. Воркер карточки `rules-vendor-srd-spell-lists` заметил это первым и написал в отчёте:
   ворота были зелёными в тот момент, когда `rules::tests` уже краснел на четвёртой теме.
2. На ужатии картинок бестиария (`d54b378`) `npm run gate` дал код 0, а `cargo test` следом
   уронил `combat::bestiary_data_tests::resized_list_thumbnail_...`. Не гони продюсер Rust-пробы
   руками — сломанная проба уехала бы в `personal`.

С тех пор в каждую карточку приходится вписывать «`cargo test` отдельным пунктом». Это лечение
симптома: правило легко забыть, и оно молчит ровно тогда, когда нужнее всего.

## Что нужно

**Ворота обязаны запускать Rust-пробы.** Смени последний шаг с `cargo check` на `cargo test`.

`cargo test` компилирует всё, что компилировал `cargo check`, **и вдобавок код проб**, и потом
их гоняет — так что держать оба шага смысла нет, это двойная компиляция. Но реши сам, посмотрев
на время: если выйдет, что раздельные шаги ощутимо быстрее за счёт кэша, оставь как считаешь
правильным и объясни решение.

**Назови в отчёте время ворот до и после** — числом, на одном и том же чистом прогоне. Сегодня
полный прогон занимает порядка 120-130 секунд; насколько он вырастет, важно знать: ворота
гоняются в каждой карточке, и лишняя минута умножается на число волн.

## Проверить, что дыра закрыта

Недостаточно, что ворота проходят. Нужно показать, что они **краснеют**:

1. Сломай любую Rust-пробу заведомо (например, поменяй ожидаемое число в
   `spells::tests::bundled_spells_json_parses_and_is_not_empty`).
2. Прогони `$GATES_CMD` целиком — он **обязан упасть**, и в выводе должно быть видно имя
   упавшей пробы, а не только «cargo завершился с ошибкой».
3. Верни починку, прогони заново — зелёный.

Это и есть главная приёмка карточки. Без шага 2 работа не сделана.

## Хвост: снять устаревшую оговорку из открытых карточек

После починки строка «`cargo test` отдельным пунктом — ворота гоняют `cargo check`» становится
неверной и будет сбивать с толку. Она стоит в двух открытых карточках:

- `tasks/open/characters-abyss-elf-race.md`
- `tasks/open/engine-event-tables-second-wave.md`

Поправить обе: требование гонять Rust-пробы остаётся, но теперь его выполняют сами ворота,
отдельного пункта не нужно. В закрытые записи `DONE.md` не лезть — там история, она верна
на свой момент.

## Что НЕ входит

- Добавление новых шагов в ворота (линтеры, форматтеры, аудит зависимостей) — это отдельный
  разговор, здесь только закрывается дыра.
- Ускорение ворот, кэширование сборки, распараллеливание.
- Починка самих проб: на момент заведения карточки все зелёные.

## DoD

- `npm run gate` запускает Rust-пробы и падает, если хоть одна красная — **показано на живой
  поломке**, а не заявлено.
- Время ворот до и после названо числом.
- Оговорка снята из двух открытых карточек.
- Ворота зелёные на чистом дереве.

## Критерии приёмки

- В отчёте приведён вывод ворот на сломанной пробе — видно имя упавшей пробы.
- Сказано словами, оставлен ли `cargo check` рядом с `cargo test` и почему.
