# dice-page-rework

Размер: M

Зона: `ui-shell`. Роль-исполнитель — `ui-developer` (см. `gamestudio/roles/ui-developer.md` и
`roles/_common.md`), не `developer`.

## Контекст

Владелец продукта потестировал «Кубики» вживую и просит переделать страницу целиком. Явно
подтверждённые решения (не предлагать альтернатив):

- **Селекторы полностью заменяют поле свободного выражения** (сейчас можно ввести `2d6+3`, `d20adv`
  — текстом). Никакого текстового ввода выражения не остаётся.
- **Дублирующееся число в скобках убирается только там, где оно реально дублирует** (один кубик без
  модификатора — итог совпадает с единственным броском). Для составных бросков (`2d6+3`)
  расшифровка по костям остаётся — там она несёт полезную информацию.

Бэкенд (`src-tauri/src/dice.rs → roll_expression`) не меняется — грамматика выражения уже
`NdM[+/-K][adv|dis]` и `roll_dice` как команда остаётся; переделка полностью на фронтенде: селекторы
собирают строку выражения и вызывают тот же `invoke("roll_dice", { expression })`.

## Что нужно

### 1. Селекторы вместо кнопок-костей и поля выражения

Заменить блок `QUICK_DICE`-кнопок и `<input>` с текстом выражения на структурный набор:
- Кость (`d4`/`d6`/`d8`/`d10`/`d12`/`d20`/`d100`) — переиспользовать уже существующий `DiceIcon` для
  визуального выбора (не голый `<select>` без иконок — иконки костей уже нарисованы, не выбрасывать
  проделанную работу).
- Количество костей — числовой селектор (1 и больше, разумный верхний предел, бэкенд ограничивает
  1-100).
- Модификатор — числовой селектор со знаком (может быть отрицательным: `-5` до `+20` с запасом,
  0 — по умолчанию, ничего не добавлять к выражению при 0).
- Преимущество/помеха — трёхпозиционный выбор (обычный/преимущество/помеха), собирает суффикс
  `adv`/`dis` у выражения. Бэкенд поддерживает это для любой кости, не только d20 — не сужать
  искусственно только до d20, хотя по правилам чаще всего это будет d20.
- Кнопка «Бросить» собирает выражение из состояния селекторов и вызывает существующий
  `invoke("roll_dice", { expression })` — сам вызов и обработка результата не меняются.

### 2. Анимация броска + звук

- По нажатию «Бросить»: короткая анимация «катящегося» кубика (вращение/смена граней иконки
  `DiceIcon` — 400-700 мс достаточно, не переусердствовать) одновременно со звуком броска (уже
  положен файл владельца — `public/audio/dice-roll.wav`, загрузить через `HTMLAudioElement`/
  `new Audio(...)`, не Web Audio синтез — здесь звук уже готовый, не выдуманный). После анимации —
  показать реальный результат (дождаться ответа `roll_dice`, не показывать случайное число во время
  анимации, которое потом не совпадёт с настоящим результатом).
- Старая функция `playDiceRollSound` (синтезированный шум, `src/audio/uiSounds.ts`) для этой кнопки
  больше не используется — реальный файл владельца её заменяет здесь. Не удалять саму функцию из
  `uiSounds.ts`, если она используется где-то ещё (проверить) — просто не звать её из `DicePage.tsx`.

### 3. Убрать дублирование числа только где оно реально дублирует

В логе бросков (`dice-page__log`): если `item.result.rolls.length === 1 && item.result.modifier === 0`
(один кубик, без модификатора — итог буквально совпадает с единственным значением в `rolls`) — не
показывать расшифровку `[...]` рядом с итогом, она ничего не добавляет. Во всех остальных случаях
(несколько костей и/или есть модификатор) расшифровка остаётся как есть.

### 4. Маленькое окно для ручной записи

Поле `manualValue` и кнопка «Записать вручную» сейчас занимают непропорционально много места
(широкий инпут). Уменьшить до размера, соразмерного вводу одного числа (2-3 символа шириной, не на
всю ширину блока).

## DoD

- На «Кубиках» нет ни кнопок быстрого выбора кости в старом виде, ни текстового поля выражения —
  только селекторы (кость/количество/модификатор/преим.-помеха) + «Бросить».
- Бросок показывает анимацию + звук из `public/audio/dice-roll.wav`, затем реальный результат.
- Расшифровка `[...]` пропадает только для одиночного кубика без модификатора; для составных
  бросков — остаётся.
- Поле ручной записи — маленькое, под размер числа.
- `$GATES_CMD` зелёный.

## Критерии приёмки

- Выбрать d20, количество 1, модификатор 0, без преим./помехи, бросить — видно анимацию, слышен звук
  из файла, результат без `[...]`-расшифровки.
- Выбрать 2×d6, модификатор +3 — расшифровка по костям видна как раньше.
- Выбрать преимущество на любой кости — в результате видно, какой из двух наборов отброшен (как
  сейчас `item.result.dropped`), поведение не потеряно.

## Критерии тестирования

- Тест, что выбор кости/количества/модификатора/преим.-помехи собирает корректную строку выражения
  перед вызовом `roll_dice` (мокнутый `invoke`, проверка аргумента).
- Тест, что расшифровка `[...]` не рендерится для одиночного кубика без модификатора и рендерится
  при составном броске/модификаторе (может унаследовать/расширить существующие тесты
  `DicePage.test.tsx`).
