# characters-condition-effect-plates

Размер: M

## Контекст

Карточка персонажа уже умеет добавлять/убирать «Состояния» (`CharactersPage.tsx`, ~строка 133-163,
`c.conditions: string[]`, подсказки берутся из `CONDITIONS` в `characterCreationData.ts` ~1192, поле
свободное — можно вписать и то, чего нет в списке). Владелец продукта потестировал и хочет, чтобы при
добавлении статуса рядом появлялась плашка с текстом «чем вредит этот статус» — и висела, пока статус
не будет убран. Явно указано: плашки должны появляться **при добавлении каждого** статуса, не только
у части.

Полные формулировки эффектов каждого состояния уже есть в `src-tauri/rules/rules.json` → секция
`appendices-conditions` (проверено чтением файла, ~строка 2550 и далее): для каждого состояния из
`CONDITIONS` там есть `heading` уровня 2 с ТОЧНО тем же текстом (например «Ослеплённое»), а сразу
следом — `list`-блок, чьи `items` и есть краткое описание вреда (например у «Ослеплённое»: «...не
может видеть и автоматически проваливает любую проверку характеристик...», «Броски атаки против
существа совершаются с преимуществом...»). Единственное исключение — «Истощение»: это `heading`
уровня 4, а следом не список, а `table` с 6 уровнями и разным эффектом на каждом (см. rules.json
~2614-2650) — структура другая, эффект зависит от уровня истощения, которого сейчас в приложении не
существует как отдельного числа (истощение хранится как обычная строка в `conditions[]`, без уровня).

## Что нужно

1. На старте приложения (там же, где уже читается `rules.json` для «Правил» — посмотреть, как это
   уже сделано, не изобретать новый способ чтения файла) извлечь из `appendices-conditions` карту
   «название состояния → массив строк эффекта» для всех состояний из `CONDITIONS`, кроме «Истощение»
   — сопоставление по точному совпадению текста `heading` с элементом `CONDITIONS`, эффект — items
   ближайшего следующего `list`-блока. Для «Истощение» подготовить отдельно вручную строку/список
   вида «Эффект зависит от уровня истощения (см. Правила → Состояния)» — не пытаться выбрать один
   уровень произвольно.
2. В `CharacterCard` (`CharactersPage.tsx`), в блоке «Состояния» (~133-163): для каждого активного
   `condition` из `c.conditions`, у которого есть эффект в извлечённой карте — показать плашку/блок
   под названием состояния с текстом эффекта (список буллетов, как в rules.json). Для состояний,
   вписанных вручную и отсутствующих в `CONDITIONS`/карте эффектов — плашки не показывать (эффект
   неизвестен), просто оставить как сейчас (название + кнопка ✕).
3. Плашка исчезает, когда состояние убирается кнопкой ✕ (уже существующий `removeCondition`) — это
   само собой следует из рендера по `c.conditions`, отдельной логики не требуется.

## DoD

- Добавление любого состояния из встроенного списка `CONDITIONS` (кроме «Истощение», для которого —
  общая напоминающая строка) показывает плашку с реальным текстом эффекта из SRD сразу под ним,
  висящую, пока состояние не убрано.
- Плашки видно у каждого добавленного состояния из списка одновременно, если их несколько.
- `$GATES_CMD` зелёный.

## Критерии приёмки

- Добавить персонажу состояние «Ослеплённое» — под ним появляется плашка с текстом эффекта (о
  провале проверок, завязанных на зрение, и помехе/преимуществе на броски атаки). Убрать состояние —
  плашка исчезает вместе с ним.
- Добавить «Парализованное» и «Отравленное» одновременно — у каждого своя плашка с верным текстом
  (не перепутаны местами).

## Критерии тестирования

- Тест в `CharactersPage.test.tsx`: добавление известного состояния рендерит текст его эффекта;
  удаление состояния убирает и плашку.
