# bug-dice-selector-overlaps-manual-input

Размер: S

Зона: `ui-shell`. Роль-исполнитель — `ui-developer` (см. `gamestudio/roles/ui-developer.md` и
`roles/_common.md`), не `developer`.

## Контекст

Владелец продукта протестировал `dice-page-rework` вживую: селектор (судя по разметке —
скорее всего «Модификатор», `<select>` с 41 значением от −20 до +20, самый длинный список из трёх)
залезает в блок ручной записи результата (`.dice-page__manual`, идёт сразу под
`.dice-page__roller` в `DicePage.tsx`/`DicePage.css`). Визуально ломает layout — исполнителю нужно
сначала воспроизвести баг вживую (запустить `npm run tauri dev`, открыть «Кубики», раскрыть каждый
из трёх селекторов — кость/количество/модификатор/режим — по очереди), а не чинить вслепую по
описанию.

## Что нужно

Найти реальную причину наложения (раскрытый список `<select>` перекрывает нижний блок; или сам
статический layout `.dice-page__roller`/`.dice-page__selectors`/`.dice-page__manual` пересчитывается
неверно на определённой ширине окна и элементы налезают друг на друга без раскрытия) и починить так,
чтобы ни один из трёх селекторов (кость/количество/модификатор/режим) не перекрывал блок ручной
записи результата (`.dice-page__manual`) ни в свёрнутом, ни в раскрытом состоянии, на разумном
диапазоне ширины окна (не только на одном фиксированном размере).

## DoD

- Ни один селектор на «Кубиках» не залезает на блок ручной записи результата, в любом их состоянии.
- `$GATES_CMD` зелёный.

## Критерии приёмки

- Открыть «Кубики», по очереди раскрыть каждый из селекторов (кость/количество/модификатор/режим) —
  ни один не перекрывает и не ломает блок «Записать вручную» ни визуально, ни функционально
  (поле ручного ввода и кнопка остаются кликабельными сразу после).

## Критерии тестирования

Визуальный баг — автотест не осмысленен, кадры до/после в `docs/qa/evidence/` обязательны.
