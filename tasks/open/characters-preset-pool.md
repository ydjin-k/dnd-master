# characters-preset-pool

Размер: XL (12 персонажей с полными данными + новая инфраструктура — не влезет в одну сессию
воркера целиком, см. «Как поступить, если не успеваешь» ниже). Зона: `engine` (данные/модель) +
`characters` (показ). Роль-исполнитель — `developer` (перенос данных и новая функциональность —
не внешний вид, `gamestudio/roles/developer.md`).

## Контекст

Владелец хочет во вкладке «Персонажи» возможность **выбрать заранее готового персонажа** вместо
прохождения мастера создания — и дальше вести его прогрессию (левел-ап, выборы архетипа,
заклинания) точно так же, как персонажей, созданных мастером.

Источник данных — 12 готовых листов персонажей 1 уровня (официальные PDF-бланки WotC, © 2014,

**Как читать PDF — `pdftoppm`/`pdftotext` не помогают** (у этих файлов ломаная кодировка
кириллицы в текстовом слое — `pdftotext` отдаёт только цифры/латиницу, буквы пустые). Рабочий
способ, которым Producer лично прочитал все 12 листов — рендер страницы в PNG через встроенный в
Windows WinRT API (`Windows.Data.Pdf.PdfDocument`) из PowerShell, затем читать PNG глазами
(инструмент `Read` показывает изображение). Рабочий скрипт (проверен, отрисовывает все страницы
файла в `$outDir`):

```powershell
Add-Type -AssemblyName System.Runtime.WindowsRuntime
$asTaskGeneric = ([System.WindowsRuntimeSystemExtensions].GetMethods() | Where-Object { $_.Name -eq 'AsTask' -and $_.GetParameters().Count -eq 1 -and $_.GetParameters()[0].ParameterType.Name -eq 'IAsyncOperation`1' })[0]
$asTaskAction = ([System.WindowsRuntimeSystemExtensions].GetMethods() | Where-Object { $_.Name -eq 'AsTask' -and $_.GetParameters().Count -eq 1 -and $_.GetParameters()[0].ParameterType.Name -eq 'IAsyncAction' })[0]
function Await($T, $R) { $m = $asTaskGeneric.MakeGenericMethod($R); $n = $m.Invoke($null, @($T)); $n.Wait(-1) | Out-Null; $n.Result }
function AwaitAction($A) { $n = $asTaskAction.Invoke($null, @($A)); $n.Wait(-1) | Out-Null }
[Windows.Storage.StorageFile, Windows.Storage, ContentType = WindowsRuntime] | Out-Null
[Windows.Data.Pdf.PdfDocument, Windows.Data.Pdf, ContentType = WindowsRuntime] | Out-Null

$pdfPath = "C:\Users\Евгений\OneDrive\Desktop\Готовые персонажи\Бард полурослик.pdf"
$outDir = "$env:TEMP\pdf-pages\бард-полурослик"
New-Item -ItemType Directory -Force -Path $outDir | Out-Null
$file = Await ([Windows.Storage.StorageFile]::GetFileFromPathAsync($pdfPath)) ([Windows.Storage.StorageFile])
$doc = Await ([Windows.Data.Pdf.PdfDocument]::LoadFromFileAsync($file)) ([Windows.Data.Pdf.PdfDocument])
$outFolder = Await ([Windows.Storage.StorageFolder]::GetFolderFromPathAsync($outDir)) ([Windows.Storage.StorageFolder])
for ($i = 0; $i -lt $doc.PageCount; $i++) {
  $page = $doc.GetPage($i)
  $outFile = Await ($outFolder.CreateFileAsync("page$i.png", [Windows.Storage.CreationCollisionOption]::ReplaceExisting)) ([Windows.Storage.StorageFile])
  $stream = Await ($outFile.OpenAsync([Windows.Storage.FileAccessMode]::ReadWrite)) ([Windows.Storage.Streams.IRandomAccessStream])
  AwaitAction ($page.RenderToStreamAsync($stream))
  $stream.Dispose(); $page.Dispose()
}
```

Producer уже отрендерил страницу 1 каждого файла и сверил расу/класс/предысторию (см. контекст
выше) — но полные данные (навыки, снаряжение, заклинания, боевые характеристики) с каждого листа
воркеру нужно перенести самому со всех страниц (обычно 2-3 на файл), этим же способом.

## Что нужно

1. **Формат данных пресетов**: новый бандленный JSON (например
   `src-tauri/characters/presets.json`), загружаемый тем же паттерном `include_str!`/загрузчика,
   что `rules::load_rules`/`spells::load_spells`/`combat::load_bestiary` — не изобретать новый
   способ. Новая Rust-команда (например `get_character_presets`) отдаёт список во фронтенд.
2. **Каждый пресет — это готовый объект `Character`** (тот же тип, что уже использует
   `CharacterWizard.tsx`/`CharactersPage.tsx`), а не отдельная урезанная структура — иначе
   прогрессия (левел-ап, `effectiveSubclassGrants`, `subclassSpellsUpToLevel`,
   `characterResources` и т.п.) не подхватит его так же, как персонажа из мастера. Заполнить все
   поля, которые мастер заполняет при создании (расы/класс/подкласс — где применимо на 1 уровне,
   способности, навыки, HP/КД/скорость/инициатива/пассивная внимательность, языки, владения,
   инвентарь, известные заговоры/заклинания, `subclassChoices` где нужно). Числа — реальные с
   листа (не пересчитывать формулами заново, если на листе указано другое — эти персонажи уже
   были собраны игроками руками и могут не совпадать с авто-расчётом мастера; расхождение не
   баг, если так на листе).
3. **UI выбора пресета**: в `CharactersPage.tsx` — рядом с кнопкой «Создать персонажа по правилам»
   (см. недавнюю карточку `ui-layout-systemic-audit-and-fixes`, если она уже слита — свериться,
   куда переехала кнопка, не конфликтовать) добавить путь выбора готового персонажа: список 12
   пресетов (имя/раса/класс), клик — персонаж копируется в ростер игрока (новый `id`, остальное
   как в пресете), сразу доступен для игры и левел-апа.
4. **Жрец-полуэльф**: домен Знаний → домен Света (см. контекст) — взять настоящие свойства/
   заклинания домена Света 1 круга, не переносить текст домена Знаний с листа.

## Как поступить, если не успеваешь за одну сессию

Сначала инфраструктура (пункты 1-3, работает на 1-2 персонажах для проверки), затем как можно
больше персонажей из списка. В отчёте явно назвать, сколько из 12 перенесено полностью, какие
остались — для карточки-продолжения.

## DoD

- Инфраструктура полностью рабочая: команда отдаёт пресеты, в UI есть выбор, выбранный пресет
  копируется в ростер как обычный персонаж.
- Хотя бы часть из 12 персонажей перенесена полностью и точно (числа с листа, не выдуманные).
- Пресет-персонаж после добавления левелится, выбирает архетип/особенности и колдует точно так
  же, как персонаж, созданный мастером — не отдельная урезанная механика.
- Жрец-полуэльф — домен Света, не Знаний.
- `$GATES_CMD` зелёный.

## Критерии приёмки

- Открыть вкладку «Персонажи», выбрать готового персонажа (например, Барда-полурослика) — он
  появляется в ростере со всеми данными с листа (характеристики, HP, КД, навыки, снаряжение).
- Повысить уровень выбранного пресета — левел-ап проходит так же, как у персонажа из мастера
  (ASI/выбор архетипа/новые заклинания появляются по тем же правилам).
- Жрец-полуэльф показывает домен Света и его заклинания/особенности, не домен Знаний.

## Критерии тестирования

- Тест, что `get_character_presets` отдаёт непустой список с ожидаемыми именами/классами.
- Тест, что добавление пресета в ростер создаёт персонажа с корректными базовыми полями
  (раса/класс/HP/КД хотя бы у одного-двух пресетов, не у всех 12 поштучно).
- Тест, что левел-ап пресетного персонажа работает тем же кодом, что и обычного (не отдельная
  ветка логики — например, общий тест на прогрессию, параметризованный источником персонажа).
