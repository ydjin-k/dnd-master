# engine-gm-debug-screen

Зона: `engine`. Размер: S. Роль: Developer.
Предусловие: `engine-gm-oracle` слита — показывать пока нечего.

Основание: ADR 0001, раздел 6 пункт 3. ТЗ: §38, §23, §41 пункт 16.

## Зачем это в первой пачке, а не «когда-нибудь»

§38 — **единственный способ проверить арифметику Оракула**: базовая вероятность → модификаторы →
итог → бросок → исход. Отладочный экран, пришедший после Оракула через три пачки, означал бы, что
Оракул всё это время принимали на слово.

Поле `trace` заполняется начиная с карточки ядра, и к этому моменту оно уже есть в каждом ответе.
**Здесь делается только экран** — поэтому S, а не M.

## Что нужно

Показ `ResultObject.trace` последнего действия и сида кампании:

```
Действие      → ORACLE
Вопрос        → door_has_guard (текст игрока, в логике не участвует)
Базовая       → 50 (равные шансы)
Модификатор   → +1 (крепость охраняется) → 70
Бросок        → 82 (сид 481922, обращение №14)
Исход         → NO
Факт          → создан: door_03.guard = false
Лог           → строка добавлена
```

- **Видно, когда броска не было.** Главная строка отладки — «ответ из факта, бросок не
  выполнялся» (§6.3). Ради неё экран и нужен.
- Сид и номер обращения к ГСЧ видны: без них «тот же сид — тот же результат» нечем проверить.
- Экран **не восстанавливает причину по исходу** и ничего не вычисляет: показывает то, что
  положил решавший модуль. Восстановление причины на стороне показа — ровно тот дефект, который на
  пилоте назвал 29 мирных объектов из 51 «сюда пути нет».

Включение: видимость отладки — переключатель в интерфейсе; по умолчанию выключен.

## Чего НЕ делать

- **Не хранить `trace` в состоянии.** Он живёт в одном ответе (ADR раздел 3). История решений
  §23 — это лог приключения и History Log, у них свои владельцы.
- Не заводить своего `useState` на данные движка: экран читает `state.engine.*` (признак
  опровержения ADR №2).
- Не доводить до красоты — это Developer, а не `ui-developer`. Читаемо и правдиво.
- Не показывать отладку игроку по умолчанию.

## DoD

- Экран показывает всю цепочку из §38 по последнему действию, включая сид и номер обращения к ГСЧ.
- Случай «броска не было, ответ из факта» отображается явно и отличим от случая с броском.
- Переключатель работает, по умолчанию выключено.
- **Отрицательная проба:** подменить в `trace` итоговую вероятность — проба экрана краснеет, то
  есть экран действительно показывает `trace`, а не считает сам.
- `$GATES_CMD` зелёный, числа названы.

## Критерии приёмки

- Первой строкой отчёта: **что экран показывает, чего нельзя узнать иначе.**
- Названо числом: проб было / стало.

## Критерии тестирования

- **Наблюдаемым поведением игры, и это главная проверка всей пачки:** в живом окне задать Оракулу
  вопрос, на отладочном экране увидеть арифметику и бросок; задать тот же вопрос повторно — увидеть
  «ответ из факта, бросок не выполнялся»; создать вторую кампанию с тем же сидом, повторить ту же
  последовательность и увидеть те же числа.
- Порт 1420 занят владельцем: свой порт, свой bundle id, гасить только по PID своего запуска,
  `taskkill //IM dnd-master.exe` ЗАПРЕЩЁН.
