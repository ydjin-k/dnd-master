# rules-spells-data-level-2-5

Размер: L

## Контекст

Владелец продукта хочет заклинания 2-5 круга. Сейчас `src-tauri/rules/spells.json` (тип `Spell` в
TS+Rust) содержит только заговоры и заклинания 1 круга — 24 + 47 = 71 запись, только для шести
классов заклинателей 1 уровня (см. `rules-spells-data`). `rules.json` (перевод longstoryshort.app)
**не содержит раздела с полным текстом заклинаний вообще** (проверялось при создании
`rules-spells-data`) — как и тогда, источник текста/цифр заклинаний — **официальный WotC SRD 5.1
PDF** (`media.wizards.com/2016/downloads/DND/SRD-OGL_V5.1.pdf`, CC BY 4.0, открытая лицензия), не
`rules.json` и не память о D&D. Переводить на русский самостоятельно, тем же процессом, что и в
`rules-spells-data`.

Объём подтверждён владельцем продукта: **заклинания 2, 3, 4 и 5 круга** (не полный список до 9
круга — персонажи сейчас ограничены уровнями 1-5, `characters-leveling-1-5`, на 5 уровне заклинатель
доходит максимум до ячеек 3 круга; уровни 4-5 круга берутся с запасом на случай будущего расширения
левелинга, но не выше — владелец продукта явно выбрал именно диапазон 2-5, не полный SRD).

**Эта карточка — только данные**, по образцу `rules-spells-data`: наполнить `spells.json` новыми
записями (`level: 2..5`) для тех же шести классов, что уже покрыты (Бард/Жрец/Друид/Чародей/
Колдун/Волшебник — сверить точный список по уже существующему `spells.json`, не гадать). **Не**
входит в эту карточку: подключение этих заклинаний к мастеру персонажа/левел-апу (выбор заклинаний
2+ круга при повышении уровня, ячейки заклинаний 2+ круга у персонажа) — это отдельная будущая
карточка поверх `characters-leveling-1-5`, которая явно оставила текущее ограничение («заклинания
2+ круга — пока в разработке») и должна остаться таковым до той карточки. Здесь только пополняется
`get_spells`/страница «Правила» (спелл-браузер там уже существует и подхватит новые заклинания
автоматически, если формат данных не менять).

## Что нужно

1. Собрать список всех заклинаний 2-5 круга из официального SRD PDF для шести уже покрытых классов
   (класс есть в списке заклинания, если PDF указывает, что этот класс может его получить — тот же
   критерий, что уже использован в `rules-spells-data`).
2. Для каждого — заполнить те же поля, что уже есть у `Spell` (`id, name, level, school, castingTime,
   range, components, duration, concentration, ritual, classes, description, damageDice,
   damageType, attackRoll` — сверить точный список полей в `state/types.ts`/`model.rs` перед
   стартом, не полагаться на пересказ здесь), переведённые на русский самостоятельно, числа/кости
   урона и т.п. — точно по тексту PDF, не по памяти о D&D.
3. Добавить записи в `spells.json` теми же id-конвенциями, что уже используются (посмотреть паттерн
   существующих id заклинаний 1 круга).

## DoD

- `spells.json` содержит заклинания 2, 3, 4 и 5 круга для всех шести уже покрытых классов, с теми же
  полями, что и существующие записи.
- Страница «Правила» → браузер заклинаний показывает новые заклинания без дополнительных изменений
  кода (если формат данных не менялся) — проверить вручную, что это так.
- `$GATES_CMD` зелёный, включая существующие тесты, которые читают `spells.json` (если такие есть —
  проверить, что они не завязаны на конкретное количество записей).

## Критерии приёмки

- Открыть «Правила» → заклинания, найти через поиск любое заклинание 3 круга (например
  «Огненный шар»/Fireball, если он есть у Волшебника в SRD) — оно есть, с полным переведённым
  описанием и корректными цифрами (сверить вручную хотя бы 2-3 заклинания против PDF).
- Существующие заклинания 1 круга/заговоры не изменились (это чисто добавление, не правка).

## Критерии тестирования

- Если существует тест на структуру/количество `spells.json` — обновить ожидаемое количество или
  сделать тест менее хрупким (например проверять наличие конкретных полей у каждой записи, а не
  точное число записей).
