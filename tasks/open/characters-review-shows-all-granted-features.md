# characters-review-shows-all-granted-features

Размер: M

## Контекст — новое правило от владельца продукта

**Владелец продукта сформулировал правило, которое действует на весь мастер персонажа впредь, не
только на эту карточку:** если выбор игрока (раса, класс, предыстория, любая под-опция) даёт
персонажу свойство/особенность — эта особенность обязана быть видна на шаге «Итог». Не просто
факт выбора (например, название предыстории), а САМА особенность с её эффектом.

Шаблон уже есть в коде и его и использовать: `CharacterWizard.tsx`, блок «Расовые особенности»
(~строка 1184-1195) рендерит `<strong>{t.name}</strong> — {t.description}` для каждой черты расы;
то же самое уже сделано для боевого стиля Бойца (~1196-1205). Использовать ровно этот паттерн
(`<strong>Название</strong> — описание`) для всего нового, что подпадает под правило ниже — не
изобретать другой формат.

## Найденный конкретный пробел

`background?.feature` (особенность предыстории, например «Приют для верующих: ...» у Послушника)
**нигде не выводится на «Итоге»** — сейчас там только `<li>Предыстория: {background?.title}</li>`
(~строка 1163) и золото. Все 13 предысторий имеют `feature`, ни один не показывается.

## Что нужно

1. Добавить в блок `<ul className="wizard__summary">` строку с особенностью предыстории — по
   образцу расовых особенностей: `<strong>{имя особенности}</strong> — {остальной текст}`.
   `feature` сейчас — одна строка вида `"Приют для верующих: вы и спутники..."` (название и
   описание в одной строке через двоеточие) — разбить на «до первого двоеточия» (жирным) и «после»
   (обычным текстом), либо, если так надёжнее, завести на `BackgroundData` отдельное поле
   `featureName` вместо парсинга строки — на усмотрение исполнителя, но итоговый визуальный
   результат должен быть `<strong>Название</strong> — описание`, как у расовых черт.
2. **Аудит по всему мастеру** (это и есть суть нового правила, не только предыстория): пройтись по
   всем шагам мастера и убедиться, что каждый выбор, дающий особенность/свойство, отражён на
   «Итоге» тем же паттерном. Известные кандидаты для проверки: инструмент Монаха, три инструмента
   Барда, доп. язык предыстории (уже показывается через строку «Языки», это ок — язык не
   «особенность» в смысле этого правила), любые другие классовые фичи, которые сейчас выводятся
   голым текстом без выделения имени. Если найдётся что-то ещё не показанное вообще (не только не
   жирное, а полностью отсутствующее) — исправить в этой же карточке.
3. Жирный шрифт — только для ИМЕНИ особенности (то, что до двоеточия/название), не для всего текста
   целиком.

## DoD

- Особенность каждой из 13 предысторий видна на «Итоге» с жирным названием, по образцу расовых
  черт.
- Ни одна известная на сегодня «дающая особенность» механика не пропущена на «Итоге» (по итогам
  аудита из п.2).

## Критерии приёмки

- Реальный сценарий: создать персонажа с предысторией Дворянин — на «Итоге» видно и «Дворянин» в
  строке «Предыстория», и саму особенность Дворянина отдельной строкой с жирным названием.

## Критерии тестирования

- Тест в `CharacterWizard.test.tsx`: выбрать любую предысторию, дойти до «Итога» — текст особенности
  этой предыстории присутствует в DOM.
