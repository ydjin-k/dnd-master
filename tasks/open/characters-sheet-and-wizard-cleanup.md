# characters-sheet-and-wizard-cleanup

Размер: XL — большая карточка, коммитить инкрементально по подпунктам, в отчёте явно отмечать, что
сделано, а что нет.

Зона: `ui-shell` (+ `characters` только там, где явно указано — новый бэкенд-факт «сколько персонажей
свёрнуто» не заводить, это чисто фронтенд-UI-состояние). Роль-исполнитель — `ui-developer` (см.
`gamestudio/roles/ui-developer.md` и `roles/_common.md`), не `developer`.

## Контекст

Владелец продукта прогнал живьём мастера персонажа и карточку персонажа — самый плотный список
претензий из всей сессии тестирования. Все пункты ниже подтверждены явно, делать сразу, без этапа
предложений (это не выбор цветовой темы — это конкретные баги эргономики).

## Что нужно

### 1. Шрифт: выпадающие меню vs остальной текст

Сейчас в выпадающих списках/контекстных местах (владелец явно указал: числа урона оружия и похожие
места) шрифт непропорционально огромный по сравнению с окружающим обычным текстом — выглядит как
разные системы разом. Единое правило: буквы и цифры одного размера везде, где это один смысловой
уровень текста (не заголовок). Если нужно выделить важное — цветом (уже есть акцентный цвет темы)
или жирным, а не увеличением кегля. Явно завести (или поправить, если уже есть похожее) единое
CSS-правило для `<select>`/`<option>`/списков предметов оружия, а не точечные инлайн-размеры по
файлам — «единый владелец факта» про размер шрифта уровня текста.

### 2. Гигантские поля ввода — везде

По всему листу персонажа и по мастеру: поле нового предмета (`newItemName`), поле нового состояния
(`newCondition`), поле добавления опыта (`xpInput`) в `CharactersPage.tsx`, и аналогичные текстовые/
числовые поля в `CharacterWizard.tsx` (в т.ч. поле имени персонажа, доп. поля своей предыстории) —
пройтись по всем и уменьшить каждое под реальный ожидаемый ввод (число опыта — под 4-6 цифр, не на
всю ширину карточки; текстовый поиск предмета — под разумную длину названия с `datalist`, не во всю
ширину). Не менять `<textarea>` многострочных полей (если такие есть и оправданы длинным текстом) —
это касается однострочных инпутов с большими значениями `width`/отсутствующим `max-width`.

### 3. Деньги — иконки вместо подписей, счётчик рядом

`COIN_DENOMINATIONS` (`characterCreationData.ts`) сейчас даёт только `label` вроде «мм»/«см»/«эм»/
«зм»/«пм» — владелец находит это некрасивым. Добавить туда же (единственный владелец справочника
номиналов, не дублировать) поле с иконкой на каждый номинал (медь/серебро/электрум/золото/платина —
разный цвет/форма монеты, SVG, тот же принцип, что уже применён к иконкам костей `DiceIcon`). В
`CharactersPage.tsx` (блок `character-card__coins`) — заменить текстовую подпись на иконку и
поставить кнопки −/+ вплотную к иконке и числу (визуально, не только в DOM-порядке — если сейчас
это уже рядом в разметке, но выглядит растянутым через `justify-content`/широкий флекс-контейнер,
поправить именно CSS-раскладку строки, не структуру).

### 4. Сворачиваемые карточки персонажей

Если персонажей больше одного — каждую `character-card` можно свернуть до компактного заголовка
(имя, класс/уровень, может быть HP) и развернуть обратно. Состояние свёрнутости — локальный UI-стейт
компонента (`useState`, не персистентное поле в `Character`/бэкенде — это не игровой факт, а вид
экрана). Один персонаж — не имеет значения, свёрнута карточка или нет, но при нескольких это должно
реально экономить место на экране.

### 5. Звуки

Использовать существующий синтез (`src/audio/uiSounds.ts`), тем же паттерном, что уже есть
(`playButtonClickSound`, `playDiceRollSound`) — добавить туда новые функции, не плодить второй файл со
звуками:

- Повышение уровня (`requestLevelUp`/подтверждение левел-апа в `CharactersPage.tsx`) — отдельный
  звук, не обычный клик кнопки.
- Сотворение заклинания (там, где сейчас тратится ячейка/используется заговор — найти существующий
  обработчик использования заклинания в карточке персонажа).
- Бросок кубиков при генерации характеристик методом броска (мастер персонажа, метод «бросок 4к6») —
  переиспользовать уже существующий `playDiceRollSound` из `uiSounds.ts`, не писать новый.
- Звук монет («мешочек золота») — на любое изменение `coins` где угодно в приложении, где игрок сам
  меняет число монет кнопками +/− (карточка персонажа; и в мастере, если там тоже есть ручное
  изменение золота предыстории).
- Звук отказа/лимита — ненавязчивый тематический (не резкая ошибка) звук + красная подсветка поля
  (переиспользовать существующий класс `character-card__danger`/аналог, не заводить новый) в каждом
  месте, где сейчас действие уже блокируется лимитом: возраст (`AGE_LIMIT`), золото своей
  предыстории (`CUSTOM_BACKGROUND_EQUIPMENT_LIMIT`/клэмп золота), грузоподъёмность (уже блокирует
  добавление — `addItemBlocked`/`wouldExceedCapacity`), недостаточно опыта для левел-апа
  (`canLevelUp`). Звук — при попытке превысить лимит (клик по заблокированной кнопке/попытка ввести
  большее значение), не постоянно, пока лимит достигнут.

### 6. Органичная компоновка листа персонажа

После пп. 1-5 отдельно посмотреть на карточку персонажа целиком (не точечно) — сгруппировать
логически связанные блоки (сейчас порядок разделов уже есть, но интервалы/отступы между
`<details>`-блоками и внутри них не согласованы), выровнять отступы и размеры по единой сетке, а не
оставлять ощущение «свалено друг под другом». Это не смена цветовой темы (её трогать не нужно, тема
уже выбрана владельцем в `ui-visual-and-sound-polish`) — только расстояния/группировка/выравнивание.
Кадры до/после в `docs/qa/evidence/` обязательны — правка чисто визуальная, словами не доказывается.

### 7. Мастер персонажа — тот же принцип

Пункты 1 (шрифт) и 2 (размер полей) применяются и в `CharacterWizard.tsx` целиком, не только на
карточке персонажа — пройтись по всем 6 шагам мастера.

## DoD

- Единый размер шрифта текста одного уровня везде (включая `<select>`/списки оружия), выделение —
  цветом/жирным, не размером.
- Все перечисленные поля ввода уменьшены под реальный размер значения.
- Номиналы монет — с иконками, счётчик визуально вплотную к иконке/числу.
- Карточка персонажа сворачивается/разворачивается при нескольких персонажах.
- Пять новых звуков подключены в перечисленных местах, ошибка лимита дополнительно подсвечивает поле
  красным.
- Кадры до/после компоновки листа персонажа — в `docs/qa/evidence/`.
- `$GATES_CMD` зелёный на каждом инкрементальном коммите.

## Критерии приёмки

- Открыть мастер и лист персонажа — числа урона/навыков в выпадающих местах визуально того же
  размера, что окружающий текст.
- Создать двух персонажей — у каждой карточки есть рабочая кнопка свернуть/развернуть.
- Повысить уровень — свой звук, не клик. Попытаться превысить лимит (например добавить предмет на
  максимуме грузоподъёмности) — звук отказа + поле/кнопка подсвечены красным.
- Изменить любую монету +/− — звук монет.

## Критерии тестирования

- Тест, что функции новых звуков (`uiSounds.ts`) вызываются из соответствующих обработчиков
  (левел-ап, изменение монет, отказ по лимиту) — мок функции звука, проверка вызова.
- Тест на сворачивание карточки персонажа (клик по заголовку скрывает/показывает содержимое).
