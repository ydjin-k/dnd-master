## Контекст — часть 1: тема дневника не похожа на утверждённый макет

Владелец продукта выбрал вариант C (`journal-theme-variant-c-leather-grimoire`) из трёх макетов в
`docs/art/inbox/`, ожидая, что дневник будет выглядеть **буквально как референс**
(`docs/art/inbox/journal-theme-variant-c-leather-grimoire.svg`): раскрытая книга-гримуар — две
страницы разворота, латунный корешок по центру, записи расположены как рукописный текст на левой/
правой странице. Реализация (`journal-theme-implement-leather-grimoire`, коммит есть в
`tasks/DONE.md`) взяла из референса только палитру (тёмно-синяя кожа, латунь), декоративный корешок-
полоску слева и шрифт Caveat, но раскладка осталась прежней — одна колонка карточек-записей друг под
другом (`src/ui/pages/JournalPage.css`, `.journal-page__list`/`.journal-entry`), а не разворот книги.
Владелец проверил и явно указал на расхождение с картинкой.

## Что нужно — часть 1

Переработать `src/ui/pages/JournalPage.css` (и, если совсем необходимо для структуры, минимально
`JournalPage.tsx` — но по возможности обойтись CSS/раскладкой без изменения логики компонента) так,
чтобы страница реально читалась как **разворот раскрытой книги**, а не список карточек:

- Видимый **центральный корешок** (латунная вертикальная полоса), делящий страницу на левую/правую
  половины — не только левый декоративный край, как сейчас.
- Обе половины визуально — страницы книги (текстура/оттенок бумаги-кожи из референса), а не единый
  сплошной фон под список.
- Записи дневника располагаются по страницам разворота (например, попеременно
  левая/правая половина, или сплошной поток, перетекающий с левой страницы на правую) — референс
  показывает по одной записи на каждой половине как пример, но это статичная картинка на 2 записи;
  реальный список может быть длиннее и должен листаться/прокручиваться — решить самому, как это
  выглядит естественно для книги с множеством записей (например, вертикальный скролл всего разворота,
  либо постраничное пролистывание — на усмотрение `ui-developer`, но результат должен **читаться как
  книга**, а не как текущий список).
- Сохранить существующую функциональность без регрессий: добавление записи (форма), удаление записи
  (кнопка), пустое состояние (`.journal-page__empty`), мобильная адаптивность (текущий breakpoint
  560px), звук пера при сохранении (`quill-scratch.mp3`, уже работает — не трогать).
- Заголовок «ДНЕВНИК ПУТЕШЕСТВИЙ» (референс использует такую надпись сверху) — можно оставить текущий
  `<h2>`, стилизовать под верх разворота.

## Контекст — часть 2: баг с ручным вводом на «Кубиках» — не исправлен

Ранее уже была карточка `bug-dice-selector-overlaps-manual-input` (см. `tasks/DONE.md`), но владелец
продукта, протестировав сейчас, сообщает, что баг **всё ещё воспроизводится**: разворачивающийся
инлайн-список одного из селекторов («Количество»/«Модификатор»/«Режим», `.dice-page__selectors` в
`src/ui/pages/DicePage.tsx`/`.css`) визуально оказывается **прямо там же, где находится поле ручного
ввода результата** (`.dice-page__manual input`, ниже `.dice-page__roller` в разметке) — то есть
предыдущий фикс не полностью решил проблему или регрессировал. Считать это **открытым багом**, не
предполагать, что старый коммит уже всё закрыл — воспроизвести живьём в браузере/приложении и
разобраться в реальной причине (растянутый `select[size]` не полностью раздвигает `grid`/`flex`
разметку `.dice-page__roller`, из-за чего последующий блок наезжает; либо иной механизм — увидеть
своими глазами, не гадать по коду).
