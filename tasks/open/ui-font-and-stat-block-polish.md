# ui-font-and-stat-block-polish

Размер: M (три точечных, но затрагивающих много экранов правки — заголовочный шрифт каскадом влияет на
весь интерфейс, поэтому широкий визуальный прогон обязателен).

## Контекст

Владелец продукта: шрифт и чекбоксы в приложении выглядят «сухо и не ровно», строка характеристик персонажа
(здоровье/броня/инициатива и т.д.) — «всё навалено». Producer собрал черновик-сравнение на реальном тексте
приложения и владелец выбрал направление — см. решения ниже, реализовывать нужно точно их, не заново
придумывать вариант.

**Найденная причина «сухости» шрифта**: `--dm-font-display: "Asset Fantasy", Georgia, ...` (`theme.css`)
объявлен на `h1`/`h2`/`h3`/`th`/`summary`, но у шрифта `Asset Fantasy` **нет глифов кириллицы** — весь русский
текст молча откатывается на `Georgia` из резервного стека. Почти весь текст приложения на русском, поэтому
задуманный «фэнтезийный» вид заголовков фактически нигде не виден, кроме отдельных латинских фрагментов
(«D&D Master»). Владелец увидел сравнение и выбрал замену.

## Что нужно

### 1. Заголовочный шрифт → Alegreya

- Скачать статические файлы шрифта **Alegreya** (OFL-лицензия, Google Fonts) — начертания **500 (Medium)** и
  **700 (Bold)** как минимум (в приложении заголовки сейчас используют `font-weight: 400` на `h1`-`h3`, но у
  Alegreya регулярное начертание визуально светлее «фэнтезийного» духа — подобрать вес по факту так, чтобы
  смотрелось увесисто, не тонко; можно и переставить `font-weight` в местах использования `--dm-font-display`,
  если понадобится).
- Забандлить **локально** в `public/fonts/` (как уже сделано с `Asset-Regular.ttf`/`SourceSerif4-Variable.ttf`/
  `Caveat-Variable.ttf`) — приложение офлайн-автономное (см. GAME.md), **не подключать Google Fonts по сети**,
  тем же паттерном `@font-face` + `src: url("/fonts/...")`, что уже есть в `theme.css`.
- Заменить `Asset Fantasy` на `Alegreya` в `--dm-font-display` (сам `@font-face` для `Asset Fantasy` и файл
  `Asset-Regular.ttf` можно оставить неиспользуемыми либо убрать — на усмотрение, но нигде больше не
  ссылаться).
- `Source Serif 4` (текст) не трогать — с кириллицей там всё в порядке, менялся только заголовочный шрифт.
- Прогнать приложение вживую и проверить заголовки на нескольких разных экранах (Журнал, Бестиарий, Правила,
  Мастер персонажа, Циферблат) — шрифт каскадный, эффект должен быть виден везде, где раньше был откат на
  Georgia.

### 2. Строка характеристик персонажа → плитки с подписями

`.character-card__hp` в `CharactersPage.tsx`/`.css` — сейчас одна строка текста через «·»
(`HP 24/24 · КД 18 · Скорость 30 фт · Иниц. +1 · Пас. внимательность 13 · Вес: 42 / 150 фнт.`). Заменить на
плитки со значением и подписью под/над числом (см. образец в присланном черновике-сравнении — направление
одобрено), но **важное уточнение владельца, которого в черновике не было**: плитки не должны быть одного
фиксированного размера — размер каждой плитки должен соответствовать её собственному содержимому (короткое
значение вроде «КД 18» — компактная плитка, длинное вроде «HP 24/24» — шире по факту содержимого), а не
одинаковая жёсткая сетка на все значения. Практически: не CSS Grid с равными колонками — flex-обёртка
(`flex-wrap`, `gap`) с плитками, каждая по ширине своего содержимого (`width: fit-content`/`flex: 0 0 auto`,
без принудительного растягивания). Это не логика — набор и подсчёт самих значений (HP/КД/скорость/инициатива/
пассивная внимательность/вес) не менять, только их представление.

### 3. Чекбоксы — в цвет темы

Ни одного собственного правила для `input[type="checkbox"]` в проекте нет — используется голый системный вид.
Добавить в `theme.css` `accent-color: var(--dm-accent)` на `input[type="checkbox"]` (простой и надёжный способ,
Tauri/webview на современном движке его поддерживает) — если после проверки вживую выглядит недостаточно
«в теме» (слишком похоже на браузерный чекбокс даже с accent-color), можно сделать полностью кастомный вид
(`appearance: none` + свой квадрат с рамкой `var(--dm-border)` и заливкой `var(--dm-accent)` при отметке) — на
усмотрение по итогу визуальной проверки, не обязательно оба варианта.

## DoD

- Заголовки по всему приложению используют Alegreya с полной кириллицей (визуально проверено на нескольких
  экранах, не только на карточке персонажа).
- Строка характеристик персонажа — плитки с подписями, каждая по размеру своего содержимого, не единая жёсткая
  сетка.
- Чекбоксы окрашены в акцентный цвет темы.
- `npm run gate` зелёный.

## Критерии приёмки

- Открыть любой экран с заголовками (Журнал/Правила/Бестиарий) — видно «книжный» шрифт с кириллицей, не
  Georgia.
- Открыть карточку персонажа — характеристики видны плитками, короткие значения компактнее длинных, ничего не
  обрезано и не съехало на реальных данных.
- Отметить любой чекбокс в приложении (например, владения в мастере персонажа) — цвет отметки соответствует
  акцентному цвету темы, а не системному синему/чёрному.

## Критерии тестирования

- Существующие тесты `CharactersPage.test.tsx`, читающие текст характеристик (если такие есть — проверить
  по тексту `HP`/`КД`/значениям), не должны сломаться от смены разметки на плитки; при необходимости
  поправить селекторы теста на новую структуру, не на старую строку.
