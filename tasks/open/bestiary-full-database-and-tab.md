# bestiary-full-database-and-tab

Размер: XL (50 тварей с полными стат-блоками — большая карточка, скорее всего не влезет в одну сессию
воркера целиком, см. «Как поступить, если не успеваешь» ниже).

**Карточка переписана Producer'ом перед этим диспетчем — предыдущая версия была устаревшей в двух
местах, важных для объёма и подхода к картинкам (см. правки ниже, не путать со старой версией из
истории git).**

## Контекст

Владелец продукта хочет отдельную вкладку «Бестиарий» в приложении: список тварей SRD 5.1, у каждой —
картинка. **Актуальная цель — 50 тварей, не «весь бестиарий SRD» (300+)** — более раннее решение
владельца было шире, но он сузил его до 50; не ориентироваться на цифру 300+, если она встретится в
старых записях/памяти.

**Важная находка (ускоряет задачу, не игнорировать):** в кодовой базе уже ЕСТЬ заготовка под это —
`src-tauri/src/combat.rs`: `MonsterTemplate` (id/name/maxHp/armorClass/speedFeet/attackBonus/
damageDice) и `pub fn demo_bestiary()`, сейчас содержащий всего 3 монстров-заглушки (Волк, Оборотень,
Разбойник) с комментарием в коде: «Упрощённые ориентировочные статы, не точные блоки SRD... Настоящий
бестиарий — отдельная задача по содержимому». Есть уже `#[tauri::command] fn get_bestiary()`,
используемая `start_combat`. **Не изобретать параллельную систему** — расширить именно эту.

`src-tauri/rules/rules.json` (перевод longstoryshort.app) **не содержит раздела про чудовищ вообще**
(проверено — нет секции `bestiary*`/`monster*`). Значит, как и для заклинаний
(`rules-spells-data`), полные тексты стат-блоков нужно брать напрямую из официального SRD 5.1 PDF
(`media.wizards.com/2016/downloads/DND/SRD-OGL_V5.1.pdf`, CC BY 4.0, раздел Monsters) и переводить на
русский самостоятельно — не по памяти о D&D, копировать реальные числа/тексты из PDF.

**Картинки — НЕ с Wikimedia Commons (более раннее решение сменилось), а собственный сгенерированный ИИ
арт владельца.** Владелец сам рисует/генерирует по одной карточке-арту на тварь и складывает сырые файлы в
`src-tauri/bestiary/images/` — сейчас там уже лежит **~310 таких файлов** с бессмысленными именами
(`ChatGPT Image <дата>, <время> (<n>).png`) вперемешку с уже правильно названными по-русски файлами
(`Дракон.png`, `Кентавр.png` и т.п.) — то есть какая-то часть уже сама сложилась в читаемые имена, а
часть ещё нет. **На каждой картинке в подписи/баннере впечатано название твари по-русски** — открой
файл (инструмент Read показывает изображение) и прочитай название прямо с картинки, чтобы понять, какой
твари она принадлежит. Это работа по сопоставлению существующего файла существующему имени, а не
рисование/выбор арта — она разрешена и ожидается от воркера (см. правило проекта: «читать впечатанное
название с картинки и сопоставлять самому, не спрашивать владельца, где какой файл» — устоявшийся
процесс на этом проекте). Атрибуция не нужна — это не стороннее лицензированное фото, а собственный арт
владельца, поле под атрибуцию можно не заводить вовсе.

**Если по итогу перебора всех ~310 файлов для конкретной твари из списка 50 не находится ни одной
подходящей картинки** — это единственный случай, когда нормально остановиться и спросить владельца
(попросить дорисовать/загрузить), а не спрашивать заранее или гадать раньше, чем реально перебраны все
файлы.

## Что нужно

1. **Схема данных** (`MonsterTemplate` в `combat.rs` + зеркальный TS-тип): расширить существующие
   поля новыми — как минимум `challengeRating: String` (CR), `creatureType: String` (тип существа —
   зверь/нежить/гуманоид и т.п.), `size: String`, `description: String` (краткое лором-описание,
   если есть в PDF), `traits: Vec<String>` (особые свойства текстом), `actions: Vec<String>`
   (действия текстом, помимо уже структурированной `attackBonus`/`damageDice` для основной атаки —
   участвующей в бою), `imageAsset: Option<String>` (относительный путь до забандленного файла
   картинки). Атрибуция не нужна (см. контекст выше) — поле под неё не заводить. Существующие боевые
   поля (hp/ac/speed/attack/damage) не переименовывать — `start_combat`/бой их уже использует.
2. **Данные**: заменить `demo_bestiary()` (хардкод в коде) на загрузку из бандленного JSON-файла
   (`src-tauri/bestiary/bestiary.json` или аналогично, тем же паттерном `include_str!`/загрузчика,
   что уже есть у `rules::load_rules`/`spells::load_spells`) — наполнить реальными тварями SRD 5.1 из
   официального PDF, **цель — 50 тварей**. Для каждой — картинка, найденная среди уже лежащих в
   `src-tauri/bestiary/images/` файлов (см. контекст про OCR-подбор), переименованная в
   ASCII id-based имя (`bandit.png`, по образцу уже существующих трёх).
3. **Rust-команда**: `get_bestiary` уже существует — переключить её источник данных на новый JSON
   (сохранить сигнатуру, чтобы `start_combat`/бой не пришлось трогать).
4. **Новая вкладка «Бестиарий»**: `AppShell.tsx` (добавить `"bestiary"` в `Tab`), `App.tsx`
   (добавить `case`), новая `BestiaryPage.tsx` — список тварей с картинкой, поиском/фильтром по
   имени (тот же паттерн поиска, что уже есть на странице «Правила», `rules-page-search`), клик по
   твари — разворачивает полный стат-блок (хиты/КД/скорость/CR/тип/свойства/действия).
5. Картинки нужно отдавать во фронтенд — посмотреть, как уже раздаются бандленные бинарные ресурсы в
   этом проекте (например `pdfium`/`models` папки в `src-tauri`, если там уже есть механизм отдачи
   файлов Tauri-командой или через `convertFileSrc`/`asset://` протокол) и переиспользовать тот же
   способ, не изобретать новый.
6. **Уборка сырых файлов**: после того как N файлов из ~310 распознаны и переименованы под конкретных
   тварей, оставшиеся нераспознанные/неиспользованные сырые файлы **не удалять** — оставить как есть в
   той же папке (это материал для будущих тварей/карточек-продолжений), просто не включать в
   `bestiary.json`.

## Как поступить, если не успеваешь за одну сессию

50 тварей с полными стат-блоками и подобранными картинками — заметный объём. **Коммитить
инкрементально** (по мере накопления, а не одним финальным коммитом) и в конце отчёта явно указать:
сколько тварей из 50 реально добавлено с данными и картинкой, какие остались (список имён/ID) — чтобы
можно было отправить карточку-продолжение именно на оставшееся, без повторной работы над уже готовой
инфраструктурой (схема/UI/загрузчик должны быть закончены и рабочие в любом случае, даже если тварей
набито не 50, а меньше).

## DoD

- Инфраструктура полностью рабочая: `MonsterTemplate` расширен, `get_bestiary` отдаёт данные из
  бандленного JSON, вкладка «Бестиарий» существует, показывает список с картинками, поиском и полным
  стат-блоком по клику.
- Бой (`start_combat`/`CombatPage`) продолжает работать с новыми/старыми тварями без регрессий.
- Хотя бы часть из 50 тварей реально наполнена (см. «Как поступить, если не успеваешь» — отчёт явно
  называет прогресс).
- `$GATES_CMD` зелёный.

## Критерии приёмки

- Открыть вкладку «Бестиарий» — виден список тварей с картинками; клик по одной показывает полный
  стат-блок.
- Начать бой с любой тварью из нового списка — работает как раньше (хиты/КД/атака подтягиваются).
- Приложение работает офлайн (без интернета) — картинки уже лежат локально, не подгружаются с сайта.

## Критерии тестирования

- Тест, что `get_bestiary`/`BestiaryPage` рендерит хотя бы несколько реальных тварей (не 3
  демо-заглушки).
- Существующие тесты боя (`CombatPage.test.tsx` и т.п.) остаются зелёными без изменений логики боя.
