# bestiary-image-loading-hang

Размер: M. Зона: `engine` (Rust) + `characters`/`bestiary` (фронтенд), файлы `src-tauri/src/combat.rs`
(`load_bestiary_image`), `src-tauri/src/lib.rs` (`get_bestiary_image`), `src/ui/pages/BestiaryPage.tsx`.
Роль-исполнитель — `developer` (это про производительность загрузки данных, не про внешний вид —
зона Developer, см. `gamestudio/roles/developer.md`).

## Контекст

Владелец продукта: при переходе на вкладку «Бестиарий» приложение зависает. Причина найдена
Producer'ом в коде, не предположена:

`BestiaryPage.tsx` — как только приходит список из 50 тварей (`get_bestiary`), второй `useEffect`
(строки 38-55) **сразу и одновременно** запускает `invoke("get_bestiary_image", ...)` для всех 50
тварей — без очереди, без ограничения, без ленивой подгрузки по видимости.

`combat::load_bestiary_image` (`combat.rs` строка 80-97) на каждый такой вызов читает **весь
оригинальный файл картинки целиком** (`std::fs::read`), кодирует его в base64 и отдаёт как
`data:image/png;base64,...` строку — без какого-либо уменьшения размера/разрешения.

Реальные числа (посчитаны Producer'ом на текущих 50 файлах, не оценка на глаз):
- Сырых байт картинок суммарно: **137.4 МБ** (в среднем 2.75 МБ на файл, до 3.3 МБ у самого
  тяжёлого).
- После base64 (+33%): **~183 МБ**, которые вкладка пытается пропихнуть через Tauri IPC
  практически одномоментно (50 параллельных `invoke`) при одном открытии вкладки.
- Разрешение картинок — около 1122×1402px (проверено на `giant-octopus.png`) — а показываются они
  и мелкой иконкой в списке (`bestiary-thumb--list`, десятки пикселей), и один раз крупно в деталях
  (`bestiary-thumb--detail`) — то есть текущий байт-размер избыточен для обоих случаев показа, не
  только для списка.

В проекте уже есть зависимость `image = "0.25"` (Cargo.toml) — используется для OCR-препроцессинга
в `import.rs`, можно переиспользовать для уменьшения картинок, не заводя новую зависимость.

## Что нужно

1. **Не гонять 50 картинок полного размера через IPC одновременно.** Варианты (выбрать и
   обосновать в отчёте, не обязательно оба):
   - Отдавать для списка (`bestiary-thumb--list`) уменьшенную превьюшку (например, по длинной
     стороне ~150-200px — подобрать так, чтобы реально помещалось в интерфейс, не только по числу),
     а не оригинал. Байт-размер такой превьюшки должен быть на два порядка меньше оригинала.
   - Картинку в детальном размере (`bestiary-thumb--detail`) отдавать/загружать только для
     **выбранной** твари (уже так и просится сделать из-за `selectedId`), не для всех 50 сразу.
   - Не обязательно решать двумя отдельными командами — можно одной командой с параметром желаемого
     максимального размера, если так проще; главное — байты, которые реально идут по IPC на
     открытие вкладки, должны быть на порядки меньше 183 МБ.
2. **Уменьшение делать на стороне Rust** (`image` crate, `resize`/`thumbnail`) перед base64-
   кодированием — сравнить итоговый размер до/после на тех же 50 файлах и назвать числа в отчёте.
3. Если уменьшенные версии генерировать имеет смысл кэшировать (на диск рядом с оригиналами или в
   памяти на время сессии приложения), а не пересчитывать на каждый повторный переход на вкладку —
   на выбор воркера, но не обязательно, если пересчёт на лету уже достаточно быстрый (замерить и
   назвать число, не гадать).
4. Открытие вкладки «Бестиарий» должно быть быстрым и не подвешивать интерфейс — заметно и
   измеримо (не просто «стало быстрее на глаз»).

## DoD

- Открытие вкладки «Бестиарий» с текущими 50 тварями не подвешивает интерфейс — заметно быстрее,
  числа «до/после» (суммарные байты, переданные по IPC при открытии вкладки, и/или время до готовой
  прорисовки) названы в отчёте.
- Список тварей и детальный вид всё ещё показывают картинки корректно (не пустые/битые).
- Бой (`start_combat`/`CombatPage`) не регрессирует — он использует ту же модель `MonsterTemplate`,
  но картинки в бою не показывает, так что этой карточке боя не касаться, только проверить, что
  `get_bestiary`/`start_combat` не сломаны.
- `$GATES_CMD` зелёный.

## Критерии приёмки

- В живом Tauri-приложении перейти на вкладку «Бестиарий» — приложение не подвешивается, список и
  выбранная тварь с картинками появляются быстро.
- Кликнуть по нескольким тварям в списке подряд — детальная картинка каждой появляется без
  повторного зависания.

## Критерии тестирования

- Тест на уменьшенный размер: сгенерированная превьюшка/детальная картинка заметно (в разы) меньше
  оригинального файла по байтам — не полагаться на визуальный осмотр.
- Если добавлена ленивая загрузка только выбранной твари — тест, что при смене `selectedId`
  запрашивается именно новая картинка, а не все 50 сразу при монтировании страницы.
